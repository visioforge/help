## Delphi example: record a webcam or an IP camera to MP4

Both procedures follow the TVFVideoCapture guide in the documentation: choose the source, set the output file and format, pick the mode, then call Start. The ActiveX control has the same properties.

### Delphi

Delphi

Collapse

Copy

```delphi
procedure TForm1.StartCapture;
begin
  // Devices by display name, as listed by Video_CaptureDevices_GetItem
  VideoCapture1.Video_CaptureDevice := cbVideoDevices.Text;
  VideoCapture1.Audio_CaptureDevice := cbAudioDevices.Text;
  VideoCapture1.Audio_RecordAudio := True;
  VideoCapture1.Audio_PlayAudio := False; // no speaker monitoring while recording

  VideoCapture1.Output_Filename := 'C:\Videos\capture.mp4';
  VideoCapture1.Output_Format := Format_MP4;

  VideoCapture1.Mode := Mode_Video_Capture;
  VideoCapture1.Start;
end;

procedure TForm1.CaptureIPCamera;
begin
  // RTSP over TCP through the FFmpeg engine; IP_Auto_VLC uses the bundled VLC source
  VideoCapture1.IP_Camera_URL := 'rtsp://user:password@192.168.1.100:554/stream';
  VideoCapture1.IP_Camera_Type := IP_RTSP_TCP;

  // Record the camera's own audio, not a local microphone (as in the IP Capture demo)
  VideoCapture1.IP_Camera_Audio_Capture := True;
  VideoCapture1.Audio_RecordAudio := True;
  VideoCapture1.Audio_PlayAudio := False;

  VideoCapture1.Output_Filename := 'C:\Videos\camera.mp4';
  VideoCapture1.Output_Format := Format_MP4;

  VideoCapture1.Mode := Mode_IP_Capture;
  VideoCapture1.Start;
end;
```

## Frequently Asked Questions

### What does the All-in-One Media Framework include?

The framework bundles three core libraries: Video Capture for recording from webcams, IP cameras, and screens; Video Edit for cutting, joining, and processing video files; and Media Player for playing video, audio, DVDs, and network streams. All cores include video and audio effects, frame grabbing, and on-screen display.

### Which Delphi versions are supported?

The framework supports RAD Studio and Delphi versions from Delphi 6 through the latest RAD Studio release. It provides native VCL components for seamless integration into Delphi projects. Both 32-bit and 64-bit compilation targets are supported.

### Can I use the framework with ActiveX and VB6?

Yes. The framework provides ActiveX controls that work with Visual Basic 6, C++ Builder, and any COM-compatible development environment. The ActiveX components offer the same full feature set as the Delphi VCL components.

### What video capture sources are supported?

The framework supports USB webcams, DV/HDV camcorders, TV tuners, IP cameras (RTSP, HTTP, MMS), and screen capture. Several sources can be combined into one picture-in-picture video. DV/HDV camcorders and TV tuners are supported on Windows only.

### Does the framework include a media player component?

Yes. The Media Player core plays all popular video and audio formats, DVDs, Blu-ray discs, and network streams. It includes features like frame-by-frame navigation, playback speed control, audio visualization, subtitle rendering, and custom video overlays.

### Is there an ActiveX control for video capture?

Yes. TVFVideoCapture ships both as a Delphi VCL component and as an ActiveX control, so Visual Basic 6, Visual Studio, C++ Builder and other COM hosts get the same capture features: webcams and capture cards, IP cameras, screen recording, and output to MP4, AVI, WMV and other formats. The ActiveX trial is a separate download.

### How do I connect an IP camera in Delphi?

Set IP\_Camera\_URL to the camera's RTSP or HTTP address and choose the engine with IP\_Camera\_Type, for example IP\_RTSP\_TCP for RTSP over TCP through FFmpeg or IP\_Auto\_VLC for the bundled VLC source. Then start in Mode\_IP\_Preview to watch or Mode\_IP\_Capture to record.

### Can I use FFmpeg from Delphi?

Yes, through the components rather than by calling FFmpeg libraries yourself. TVFVideoCapture reads IP camera streams with its FFmpeg engine and can write files through FFmpeg-based output formats (Format\_FFMPEGX), and TVFMediaPlayer has an FFmpeg source for files and streams.

### Can I build 64-bit Delphi applications?

Yes, from Delphi XE2 on. Add the 64-bit library path for the Win64 target and install the design-time package that matches your IDE; the 64-bit packages guide in the documentation walks through both. Visual Basic 6 applications stay 32-bit.

### Is there a free trial available?

Yes. Download the fully functional 30-day trial to evaluate all features. Depending on the engine and output, the trial may display a watermark or an unregistered notice. Both Delphi VCL and ActiveX versions are available for testing.

VisioForge was founded in 2008. The first products were Windows SDKs built on DirectShow. That classic engine still powers Video Capture SDK .NET, Media Player SDK .NET and Video Edit SDK .NET on Windows, together with the Delphi and ActiveX components of the All-in-One Media Framework.

As .NET moved beyond Windows, we built a second, cross-platform engine on top of GStreamer. The X engines — VideoCaptureCoreX, MediaPlayerCoreX and VideoEditCoreX — and the pipeline-based Media Blocks SDK .NET run the same C# code on Windows, macOS, Linux, Android and iOS.

In 2025 and 2026, releases added a complete ONVIF implementation for IP cameras, .NET 10 support, Uno Platform and Unity integration, an MCP server that gives AI coding assistants direct access to the SDK documentation, on-device AI blocks for object detection, face recognition, OCR and speech-to-text, an ASP.NET Web Forms HLS player, and native Windows on Arm support.

## Our Mission

Our mission is to empower developers by providing high-quality, reliable, and easy-to-use multimedia SDKs. We are committed to innovation, exceptional customer support, and delivering solutions that meet the evolving needs of the software development community.

## What We Offer

-   •**.NET SDKs**: Video Capture SDK .NET, Media Player SDK .NET, Video Edit SDK .NET and Media Blocks SDK .NET cover recording, playback, editing and custom media pipelines on Windows, macOS, Linux, iOS and Android. Video Edit SDK FFmpeg .NET adds FFmpeg-based editing on Windows, and Video Fingerprinting SDK, for .NET and C++, finds duplicate and pirated video.
-   •**DirectShow filters for C++, Delphi and .NET**: The FFmpeg Source and VLC Source filters, the Encoding Filters Pack and the Processing Filters Pack plug into any DirectShow application on Windows. Video Encryption SDK protects video and audio files with AES-256, and Virtual Camera SDK adds a virtual webcam and microphone that Zoom, OBS and browsers see as real devices.
-   •**Delphi and ActiveX SDKs**: The All-in-One Media Framework brings video capture, playback and editing to Delphi (RAD Studio) as native VCL components, and to VB6, C++ Builder and other COM-compatible environments as ActiveX controls.

## Cross-Platform Support

Video Capture SDK .NET, Media Player SDK .NET, Video Edit SDK .NET and Media Blocks SDK .NET run on all five major operating systems:

-   •Windows
-   •macOS
-   •Linux
-   •iOS
-   •Android

The classic engine of the first three SDKs runs on Windows only; their X engines and Media Blocks SDK are cross-platform. On Windows, these four .NET SDKs work with WinForms and WPF. Depending on the SDK, they also support WinUI, .NET MAUI, Avalonia, Uno Platform and the Unity game engine, and a separate Web Forms package adds an ASP.NET control for HLS playback in the browser. The SDKs target .NET Framework 4.6.1 and later (the Web Forms package needs 4.7.2) as well as modern .NET up to .NET 10. The DirectShow products, Video Edit SDK FFmpeg .NET and the Delphi and ActiveX components are Windows-only.

## How the scanner works

BarcodeDetectorBlock wraps the zbar barcode detector. It reads each video frame that passes through it and reports the codes it finds.

-   OnBarcodeDetected gives the barcode type, the decoded value and the timestamp of the frame on the pipeline timeline; UPC-A and UPC-E codes are reported as EAN-13
-   InputOutput mode passes the video on to a preview, an encoder or a stream; InputOnly mode only scans, for services without a screen
-   Scanning runs in the same pipeline as preview, recording and streaming, so one camera feed can be recorded and scanned at the same time
-   A code that stays in view is reported again on the following frames, so filter repeats by value in your handler
-   BarcodeDetectorBlock.IsAvailable() tells you before you build the pipeline whether the detector can run on this machine
-   Data Matrix codes are read by a separate block, DataMatrixDecoderBlock, built on libdmtx

## Frequently Asked Questions

How do I scan barcodes from a webcam in C#?▼

With Media Blocks SDK .NET, create a MediaBlocksPipeline, take the camera from DeviceEnumerator.Shared.VideoSourcesAsync(), and connect a SystemVideoSourceBlock to a BarcodeDetectorBlock in InputOutput mode and then to a VideoRendererBlock for the preview. Handle OnBarcodeDetected to get each code. With Video Capture SDK .NET, set Barcode\_Reader\_Enabled to true on VideoCaptureCoreX and handle the same event.

Can I read QR codes from an IP camera or an RTSP stream?▼

Yes. Create the source with RTSPSourceSettings.CreateAsync and RTSPSourceBlock, or with UniversalSourceBlock and the rtsp:// address, and connect its video output to BarcodeDetectorBlock. ONVIF cameras are read through their RTSP stream.

Can I use it in ASP.NET or a server-side service?▼

Yes. BarcodeDetectorBlock needs no window: in InputOnly mode it scans without rendering, so it runs in a console application, a Windows service or a background service of an ASP.NET Core application, on Windows or Linux. It reads the video that the server itself can open, such as IP camera streams, video files and capture devices attached to the server. It does not capture the camera of a visitor's browser.

Which barcode types does it read?▼

BarcodeDetectorBlock and VideoCaptureCoreX read QR Code, EAN-13, EAN-8, UPC-A, UPC-E, Code 128, Code 39, Code 93, Codabar, ITF (Interleaved 2 of 5) and GS1 DataBar (RSS-14). Both report UPC-A and UPC-E as EAN-13: a UPC-A value arrives as 13 digits with a leading 0, and a UPC-E value arrives expanded to its 13-digit form. Data Matrix is read by DataMatrixDecoderBlock. The Windows engine VideoCaptureCore also reads Data Matrix, PDF417 and Aztec, and its Barcode\_Reader\_Type property selects one type or all of them; in the default Auto mode the event reports the type as Auto.

Does it work on Linux, macOS, Android and iOS?▼

Yes. BarcodeDetectorBlock and VideoCaptureCoreX run on Windows, macOS, Linux, Android and iOS; VideoCaptureCore is Windows-only. On Windows, macOS, Android and iOS the detector comes in the VisioForge.CrossPlatform.Core.\* NuGet packages. On Linux the SDK uses the system GStreamer, so call BarcodeDetectorBlock.IsAvailable() to check that the detector is installed. Android, iOS and macOS apps also need camera permission.

Do I get the same barcode more than once?▼

Yes. The detector reports a code in every frame where it decodes it, so a code held in front of the camera arrives many times. Keep the last value and time in your handler and skip repeats within a short window, as the barcode guide shows.

Which license do I need?▼

Media Blocks SDK .NET has one edition, and the barcode detector is part of it. In Video Capture SDK .NET the barcode reader is included in every edition, Standard included; IP camera sources need the Professional or Premium edition. One Video Capture SDK .NET license covers both engines, VideoCaptureCore and VideoCaptureCoreX. Prices are in euros, and VAT is added at checkout where it applies. ## Pipeline Architecture

A VisioForge broadcasting pipeline is a chain of blocks connected in C#: a source, an optional TeeBlock that splits raw frames between a preview and the output branches, an encoder and one or more sinks. NDI and DeckLink sinks need no encoder. Sources include USB cameras, screen capture, RTSP IP cameras, NDI senders and DeckLink SDI inputs. Video is encoded to H.264 in software with OpenH264, to H.265 with SVT-HEVC on Linux, or to either on the GPU with NVIDIA NVENC, Intel Quick Sync and AMD AMF; audio is encoded to AAC. The SRT sink multiplexes these streams into MPEG-TS and supports caller, listener and rendezvous modes, a 125 ms default latency and AES passphrase encryption. The HLS sink writes MPEG-TS segments with a 5-second default target duration and can publish multivariant playlists, CMAF by default, for adaptive bitrate delivery. When the encoder's ParseStream setting is off, as for SRT, the SDK still keeps the parser for Apple VideoToolbox encoders and for H.264 on Android.

## What KLV and MISB are

KLV (Key-Length-Value, SMPTE ST 336) is the binary encoding that UAV, ISR and surveillance systems use to carry telemetry beside the video: time stamps, platform and sensor position, orientation, and the geolocation of the frame center. MISB ST 0601 (the UAS Datalink Local Set) defines those fields, and MISB / STANAG 4609 streams carry them as a separate metadata stream inside MPEG-TS.

## What the SDK does with KLV

Two VisioForge SDKs handle KLV: Media Blocks SDK works with KLV in MPEG-TS files on Windows, Linux and macOS, and Video Capture SDK passes live KLV from an IP camera or UDP source into a recording or a restream on Windows.

-   Extract: MPEGTSDemuxBlock exposes the metadata stream of an MPEG-TS file on its MetadataOutput pad, and KLVFileSinkBlock writes the KLV packets to a .klv file
-   Decode: KLVParser reads MISB ST 0601 local-set elements — more than 90 of them, from precision time stamp to sensor and frame-center coordinates — and handles the BER-encoded lengths MISB uses
-   Embed (Media Blocks): MPEGTSSinkSettings.Metadata takes a KLVMetadata object built from a .klv file or a byte array; it is muxed as one static payload, not a per-frame timed track
-   Record and restream live KLV (Video Capture SDK, Windows): MPEGTSOutput.KLVEnabled muxes KLV from the source into the MPEG-TS file, and FFMPEGEXEOutput.KLVEnabled carries it in MPEG-TS, RTP MPEG-TS and HLS output (for file recording, also set UsePipe)
-   Read live packets: the OnDataFrameBuffer event delivers each KLV packet with its size and timestamp (DataFrameType.KLV)

## A plate reader is not general OCR pointed at a car

Automatic number plate recognition — ANPR, also called ALPR, LPR or licence plate recognition — is not general OCR. General OCR reads every sign, sticker and logo in the frame and does not know which text is the plate. ANPR needs two models: a detector that finds plates and an OCR model trained on plate characters. You also need the frames — decoded from the camera, picked at a rate the hardware can keep up with, without stalling the live video. In VisioForge SDKs, LicensePlateRecognizerBlock is a block of the video pipeline: the SDK decodes the source, the block runs both models on a background thread, and the frames continue to the screen, a file or a network stream.

## Building ANPR yourself or calling a cloud API vs. LicensePlateRecognizerBlock

|  | Typical do-it-yourself or cloud ANPR | LicensePlateRecognizerBlock in a VisioForge pipeline |
| --- | --- | --- |
| Finding the plate | Find or train a plate detector, export it to ONNX, write the pre- and post-processing | FastALPR YOLOv9-T plate detector (MIT); DetectionConfidenceThreshold and MaxDetections |
| Reading the characters | General OCR that also reads every other text in the frame | A plate-specific fast-plate-ocr head; Text comes uppercased, with non-alphanumeric characters removed |
| Getting frames from the camera | A separate decoder or frame grabber for each kind of source | Any SDK source: RTSP IP cameras, webcams, video files |
| Keeping live video smooth | Recognition on the capture thread stalls the stream | Recognition runs on a background worker; frames that arrive while it is busy are skipped and counted |
| Plates from different countries | Retrain the model or change provider | A global head for the USA and 90+ countries and a European head for EU plates, chosen with RecognitionModelPath |
| Where the video goes | Frames sent to a cloud service and billed per call | Nowhere: ONNX Runtime in your process, no API key, no per-call fee |

## What the ANPR block gives you

LicensePlateRecognizerBlock ships in the VisioForge.DotNet.Core.AI package. It has one video input and one video output, runs two ONNX models on the frames it receives and reports plates through the OnPlateRecognized event.

-   Two-stage recognition: a YOLOv9-T detector finds the plates, and each cropped plate is read by a plate-specific OCR model; both are FastALPR models under the MIT license
-   A full result per plate: Text, Confidence (0 to 1), BoundingBox and the four-point Polygon in source-frame pixels, with the frame Timestamp on every event
-   Regional heads: the global head covers the USA and 90+ countries, the European head is tuned for EU plates; both read Latin characters (digits and A–Z), and the input size is read from the model itself
-   On the device: ONNX Runtime with DirectML on Windows GPUs, CoreML on Apple platforms and the CPU as fallback; ActiveProvider tells you which one is in use
-   Live video stays smooth: recognition runs on a background worker, FramesToSkip sets how often it runs, and LastInferenceTimeMs and DroppedFrameCount show how the hardware keeps up
-   Recognition next to recording: DrawResults draws the plate boxes and text into the frames that go on to the preview, a file or a stream
-   One block for every engine: connect it in a Media Blocks SDK .NET pipeline, or add it with Video\_Processing\_AddBlock to VideoCaptureCoreX or MediaPlayerCoreX

## Frequently Asked Questions

Does the video leave the machine?▼

No. LicensePlateRecognizerBlock runs both models with ONNX Runtime inside your process. There is no cloud service and no API key; frames and plate numbers stay on the device. The models are two .onnx files you ship with your application.

Which countries' plates can it read?▼

The FastALPR global recognition head covers the USA and 90+ countries; a separate European head is tuned for EU plates. Point RecognitionModelPath at the head for your region; the detector is the same for both.

Do I need to train my own model?▼

No. The block uses the FastALPR YOLOv9-T detector and the fast-plate-ocr recognition head as they are; you only supply the two .onnx files. They ship with the License Plate Recognition Demo.

What about busy scenes with many vehicles or distant plates?▼

The block reports up to MaxDetections plates per frame (10 by default). For small or distant plates, lower DetectionConfidenceThreshold or give the camera a closer view. On very busy scenes, a vehicle detector such as YOLOObjectDetectorBlock upstream can crop the vehicles first.

Which SDK do I need?▼

LicensePlateRecognizerBlock is in the VisioForge.DotNet.Core.AI package. Use it in a Media Blocks SDK .NET pipeline when you build the pipeline yourself, or add it with Video\_Processing\_AddBlock to VideoCaptureCoreX in Video Capture SDK .NET or to MediaPlayerCoreX in Media Player SDK .NET when your app already uses one of those engines.

Are license plates personal data?▼

Plates are commonly treated as personal data under privacy regulations such as the GDPR, and some jurisdictions have their own ANPR rules; review them for your use case before you deploy. To hide plates in a recording instead of reading them, PIIRedactionBlock blurs or pixelates them with the same plate detector.

## A screenshot loop is not a screen recorder

Graphics.CopyFromScreen gives you one bitmap on Windows. ## Frequently asked questions

How do I record the sound the PC is playing?▼

Use LoopbackAudioCaptureDeviceSourceSettings with an output device from DeviceEnumerator.Shared.AudioOutputsAsync(AudioOutputDeviceAPI.WASAPI2) and set Audio\_Record to true, as in the first example. For narration, use a microphone from AudioSourcesAsync instead. To record both, mix them with AudioMixerBlock in Media Blocks SDK .NET.

Can I record a window that is covered by other windows?▼

Yes, with Windows Graphics Capture: set API to D3D11ScreenCaptureAPI.WGC and WindowHandle to the window's handle. WGC captures the window's own content, so overlapping windows do not appear in the recording. A minimized window has nothing to draw and is not captured.

Does it work on macOS and Linux?▼

Yes. On macOS the screen source uses AVFoundation and needs the Screen Recording permission: ScreenSourceBlock.AskPermissions() shows the system prompt, and macOS applies a new permission after the app restarts. On Linux, ScreenCaptureXDisplaySourceSettings captures an X11 display, so the app needs an X11 session. The encoders, files and streams are the same as on Windows; system sound loopback is Windows only, so record a microphone there.

Can I record the screen on Android and iOS?▼

Yes, with Media Blocks SDK .NET. On Android, AndroidScreenCaptureSourceSettings takes the MediaProjection your app receives after the user accepts the system prompt. On iOS, IOSScreenSourceSettings records your own app through ReplayKit, and IOSBroadcastSourceSettings records the whole device through a Broadcast Upload Extension.

Why is the recording black?▼

Protected content such as DRM video is blocked from capture by the operating system. For other black frames, try the other capture API (WGC or DXGI Desktop Duplication) or the DirectX 9 source. On a laptop with two GPUs, Desktop Duplication has to run on the adapter that drives the display; DXGIAdapter selects it.

Which SDK do I need?▼

Video Capture SDK .NET if you want a ready capture engine: set Video\_Source, Audio\_Source and an output, then call StartAsync. Media Blocks SDK .NET if you build the pipeline from blocks, for example to add your own processing between the screen and the encoder. Both use the same screen sources.

## Pipeline Architecture

A Media Blocks SDK editing pipeline is a chain of blocks connected in C#: a source, optional mixer and effect blocks, an optional encoder and an output. Sources include video files through UniversalSourceBlock, cameras, screen capture and still images through ImageVideoSourceBlock. GPU effects run in an OpenGL section of the pipeline. GLUploadBlock moves frames to the GPU, GLShaderBlock runs a custom GLSL vertex and fragment shader, and GLDownloadBlock returns the frames to the CPU for encoding or display. Shader uniforms such as a blur radius can be changed while the video plays. The finished video is written by an output block such as MP4OutputBlock, which also holds the H.264 and AAC encoders. Additionally, a TeeBlock feeds the same frames to a preview window. For example, an audio track can be replaced without re-encoding the video when both codecs fit MP4: ParseBinBlock parses the original video stream, ParseBinBlock or MPEGAudioParseBlock for MP3 parses the new audio file, and MP4SinkBlock muxes both into a new MP4.

## Video OCR is not image OCR in a loop

An image OCR library takes one bitmap. To read text from a camera or a recording with it, you still decode the stream, pick frames, convert them, call the library and keep track of when each frame was shown. In VisioForge SDKs, OCR is a block of the video pipeline: the SDK decodes the source, OcrBlock reads the frames as they pass, and the same frames continue to the screen, a file or a network stream.

## Image OCR library vs OCR in the video pipeline

|  | Typical image OCR library | OcrBlock in a VisioForge pipeline |
| --- | --- | --- |
| Input | A bitmap your code passes in | Decoded frames from any SDK source: file, webcam, RTSP camera |
| Decoding the video | Your code, with a separate decoder or frame grabber | Done by the pipeline |
| Which frames are read | You pick and convert them | FramesToSkip; frames that arrive while OCR is busy are skipped and counted |
| When the text appeared | You track it yourself | Timestamp on every OnTextDetected event |
| Recording or streaming at the same time | A separate video pipeline | The same pipeline: OcrBlock output goes on to an encoder, a file or a stream |
| Boxes and text in the video | You draw them | DrawResults |

## What OCR inside the pipeline gives you

OcrBlock ships in the VisioForge.DotNet.Core.AI package. It has one video input and one video output and runs the PP-OCR models on the frames it receives.

-   Decoding is done for you: any source the SDK opens — video files, webcams, RTSP IP cameras — feeds OcrBlock directly
-   Text with time and place: each OnTextDetected event carries the frame Timestamp and, for every line, its Text, Confidence and BoundingBox
-   OCR next to recording and streaming: frames leave OcrBlock unchanged or with the text drawn in, and go on to an encoder, a file or a network output in the same pipeline
-   On the device: PP-OCR models on ONNX Runtime with the CPU, CUDA, DirectML or CoreML provider — no cloud API, no per-call fee, the video stays on the machine
-   100+ languages: point RecognitionModelPath and CharacterDictionaryPath at the PP-OCR model and dictionary for your language; the samples ship the Latin model
-   Cross-platform: Windows, macOS, Linux, Android and iOS from one C# codebase; the OCR sample also exists for .NET MAUI
-   Cost under control on live video: FramesToSkip = N runs OCR on one frame in N + 1; every setting and its default is in the OCR guide

## Frequently Asked Questions

Does the video leave the machine?▼

No. OcrBlock runs the PP-OCR models with ONNX Runtime inside your process. There is no cloud service and no API key; frames and recognized text stay on the device. The models are files you ship with your application.

How is this different from an image OCR library?▼

An image OCR library expects you to decode the video, choose frames and call it per bitmap. OcrBlock is part of the pipeline that decodes the source: it receives decoded frames, skips them according to FramesToSkip, reports each region with the frame timestamp, and passes the frames on to rendering, encoding or streaming.

Can I recognize text and record the stream at the same time?▼

Yes. Connect the OcrBlock output to an encoder and a file sink, as in the RTSP example above. DrawResults decides whether the boxes and text are burned into the recording.

Which SDK do I need?▼

OcrBlock is in the VisioForge.DotNet.Core.AI package. Use it in a Media Blocks SDK .NET pipeline when you build the pipeline yourself, or add it with Video\_Processing\_AddBlock to VideoCaptureCoreX in Video Capture SDK .NET or to MediaPlayerCoreX in Media Player SDK .NET when your app is already built on one of those engines.

Can I ship the OCR models in a commercial product?▼

The SDK runs third-party ONNX models and does not include model weights in the NuGet package. The PP-OCRv5 mobile models that ship with the samples are Apache-2.0. A model's license comes from its origin, so check the license of any other model, its weights and its training data before you ship it.

Can I combine OCR with other AI blocks?▼

Yes. LicensePlateRecognizerBlock, YOLOObjectDetectorBlock and PIIRedactionBlock have the same video input and output as OcrBlock, so they connect one after another in the same pipeline. To hide on-screen text instead of reading it, PIIRedactionBlock blurs or pixelates text regions found with the PaddleOCR models.

## Why video upload sites must detect piracy

Detecting pirated video content is essential for a new digital content era. Many types of websites offer users the ability to upload video content. Websites like YouTube exist solely for this reason, but many social networking sites also allow this capability. Such sites' immense popularity has attracted the ire of content producers who are getting serious about protecting their copyrights and putting real pressure on the owners of these types of sites to eliminate illegal infringement. A large amount of copyright-protected material – from clips from movies and TV shows to music and music videos – is readily available for download by visitors to these types of online video hosting services. While the site operators claim that they are operating under the Fair Use doctrine, content producers and large media companies aren't buying it. They have deep pockets and armies of lawyers at their disposal and are gearing up to take legal action. To avoid costly, protracted legal battles, online video upload sites pursue technologically-based methods of reducing and preventing copyright infringement on their sites.

## Detecting illegal content using Video Fingerprinting SDK

Preventing inadvertent liability for copyright infringement is a significant issue for any site that permits user-uploaded content. Copyright violations can result in costly and time-consuming legal action and could result in large civil or criminal liability. Our Video Fingerprinting SDK technology provides a perfect solution for these types of sites to continue providing video uploading and hosting of user content while minimizing the risks of copyright infringement. Video Fingerprinting SDK analyzes the content of a video, its colors, scene structure and the motion of objects, and turns it into a compact descriptor, the video fingerprint. A database of these video fingerprints can be created for copyrighted material. They can then be checked against video materials being uploaded by site users to detect the presence of copyrighted materials and disallow the posting of such materials to their websites.

## How automated piracy detection works

Video Fingerprinting SDK compares videos by their content, not by their files, so the check runs without anyone watching the uploads:

1.  Fingerprint each protected title once. A fingerprint takes about 1 KB per second of video and can be kept in a database; the .NET SDK includes a helper for MongoDB.
2.  Fingerprint each new upload, recorded broadcast or live stream as it arrives.
3.  Search the shorter video inside the longer one. The search returns the position of every match, so a clip cut from a film is found, and so is a whole film inside a longer upload. To catch an upload that mixes part of a film with other footage, fingerprint the film in short fragments (VFPFingerprintSource.StartTime and StopTime) and search each fragment inside the upload.
4.  Act on the result in your own code: block the upload, queue it for review or notify the rights holder.

## What a match survives

A fingerprint describes what is in the picture: its colors, scene structure and the motion of objects. A copy is therefore still matched after a change of resolution, bitrate, codec or file format, and a fragment is found even when it is embedded inside another video. Fingerprints can be stored, copied and compared without the original files, so the reference library does not have to sit next to the uploads.

## C# example: match an upload against a protected film

This .NET example builds fingerprints as the vfp\_gen console sample does and searches as the Media Monitoring Tool sample does. It searches the shorter fingerprint inside the longer one, so it catches a clip cut from the film as well as the whole film inside a longer upload.

using VisioForge.Core;
using VisioForge.Core.VideoFingerPrinting;

const int MaxDifference = 500; // MMT default; the MMT slider tunes it from 200 to 1000

await VisioForgeX.InitSDKAsync();
try
{
    VFPAnalyzer.SetLicenseKey("TRIAL");

    // Once per protected title: build the fingerprint and store it
    var filmFp = await VFPAnalyzer.GetSearchFingerprintForVideoFileAsync(
        new VFPFingerprintSource("protected-film.mp4"));
    if (filmFp == null) { Console.WriteLine("Cannot fingerprint the film"); return; }
    filmFp.Save("protected-film.vfp");

    // Load the stored fingerprint once, before processing uploads
    var film = VFPFingerPrint.Load("protected-film.vfp");

    // For each upload: fingerprint it, then search the shorter video inside the longer one
    var upload = await VFPAnalyzer.GetSearchFingerprintForVideoFileAsync(
        new VFPFingerprintSource("upload-1234.mp4"));
    if (upload == null) { Console.WriteLine("Cannot fingerprint the upload"); return; }

    var uploadIsShorter = upload.Duration <= film.Duration;
    var fragment = uploadIsShorter ? upload : film;
    var longer = uploadIsShorter ? film : upload;

    var positions = await VFPAnalyzer.SearchAsync(
        fragment, longer, fragment.Duration, MaxDifference, true);

    foreach (var position in positions)
    {
        Console.WriteLine(uploadIsShorter
            ? $"The upload matches the film at {position:g}"
            : $"The film appears in the upload at {position:g}");
    }
}
finally
{
    VisioForgeX.DestroySDK();
}

## What is a DirectShow filter?

A DirectShow filter is a COM component that does one step of media processing on Windows. An application connects filters into a filter graph: a source filter reads a file, a stream or a device, transform filters decode, process or encode the data, and a renderer or a file writer at the end shows or saves it. Filters ship as .ax files and are registered with Windows by an installer or regsvr32. A 32-bit application loads only x86 filters and a 64-bit application only x64 filters, so register the build that matches your app.

GStreamer Metal supports macOS 13.0 (Ventura) and later and iOS 14.0 and later. On macOS it builds as a dynamic library (gstvfmetal.dylib), while on iOS it builds as a static library (libgstvfmetal.a) with a registration header.

### What pixel formats are supported?

The plugin supports six pixel formats: BGRA, RGBA, NV12, I420, UYVY, and YUY2. Most elements support BGRA, RGBA, NV12, and I420, while vfmetalconvertscale supports all six formats for maximum conversion flexibility.

### How do I install the plugin?

Clone the GitHub repository and run the included build script (./build.sh) for macOS. For iOS, use the CMake-based cross-compilation setup. The resulting library can be placed in your GStreamer plugin path for automatic discovery.

### Is it free to use? What is the license?

Yes, GStreamer Metal is completely free and open-source, released under the GNU Library General Public License v2 (LGPL v2). You can use it in both open-source and commercial applications without licensing fees.

### What GStreamer elements are included?

The plugin provides seven GPU-accelerated elements: vfmetalcompositor (video mixing), vfmetalvideosink (display), vfmetalvideofilter (15 visual effects), vfmetalconvertscale (format conversion and scaling), vfmetaltransform (rotation/flip/crop), vfmetaldeinterlace (interlace removal), and vfmetaloverlay (image compositing).

### Can I use it in iOS apps?

Yes. For iOS, the plugin builds as a static library (libgstvfmetal.a) with a gstvfmetal\_static.h header for static registration. It integrates with the GStreamer iOS SDK and supports the video formats commonly used on iOS.

### How does GPU processing compare to CPU-based elements?

GPU-accelerated processing provides significant performance improvements over CPU-based GStreamer elements. The zero-copy architecture and single-pass processing minimize data transfers and frame buffering. Elements automatically bypass GPU work when configured at identity values, ensuring no overhead when processing is not needed.
