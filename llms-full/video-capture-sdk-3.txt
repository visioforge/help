# Enabling Camera Light on Windows 10+ Tablets

[Video Capture SDK .NET](https://www.visioforge.com/video-capture-sdk-net) [VideoCaptureCore](#)

## Introduction

Modern Windows 10+ tablets come equipped with camera light functionality that developers can control programmatically. This guide explains how to implement camera light controls in your .NET applications using the TorchControl API.

## Implementation with TorchControl API

The TorchControl API provides a comprehensive way to manage camera lights on Windows 10+ tablets. This API offers:

- Device discovery for torch-compatible cameras
- Granular control for enabling and disabling camera lights
- Cross-device compatibility

### Basic Implementation Steps

1. Initialize the VideoCaptureCore component
2. Get available devices with torch capabilities
3. Enable or disable torch functionality for specific devices

## Working Code Example

```
// Initialize VideoCaptureCore
VideoCaptureCore videoCapture = await VideoCaptureCore.CreateAsync();

// Get available devices with torch capability
string[] devices = await videoCapture.TorchControl_GetDevicesAsync();

// Enable torch for the first available device
if (devices.Length > 0)
{
    await videoCapture.TorchControl_EnableAsync(devices[0], true);
}

// Disable torch when needed
await videoCapture.TorchControl_EnableAsync(devices[0], false);
```

# Mastering Camera Image Controls in .NET Applications

[Video Capture SDK .NET](https://www.visioforge.com/video-capture-sdk-net) [VideoCaptureCore](#)

## Introduction to Camera Hardware Adjustments

When developing applications that utilize webcams or other video capture devices, having precise control over image quality parameters is essential for creating professional-grade software. The `VideoHardwareAdjustment` enum selects which hardware adjustment you are reading or writing, and the SDK exposes programmatic control over camera settings such as brightness, contrast, hue, saturation, sharpness, gamma, and more.

## Supported Hardware Adjustment Properties

The `VideoHardwareAdjustment` enum covers:

- Brightness
- Contrast
- Hue
- Saturation
- Sharpness
- Gamma
- ColorEnable
- WhiteBalance
- BacklightCompensation
- Gain
- PowerLineFrequency

Exposure, focus, zoom, and other lens-level controls live on a separate API family (`Video_CaptureDevice_CameraControl_*` + the `CameraControlProperty` enum) — this page covers hardware *image* adjustments only.

Note that not all cameras support every property. The SDK will gracefully ignore any property not supported by the specific camera hardware you're using.

## Working with Camera Adjustments

### Getting Property Value Ranges

Before setting adjustment values, it's important to understand the valid range for each property. Use the `Video_CaptureDevice_VideoAdjust_GetRangesAsync` method to retrieve the minimum, maximum, default values, and step size for any adjustment property:

```
// Retrieve the valid range of values for the brightness property
// This helps understand the boundaries within which you can adjust settings
var brightnessRange = await VideoCapture1.Video_CaptureDevice_VideoAdjust_GetRangesAsync(VideoHardwareAdjustment.Brightness);

// Check the minimum and maximum allowed values
int minValue = brightnessRange.Min;
int maxValue = brightnessRange.Max;
int defaultValue = brightnessRange.Default;
int step = brightnessRange.Step;
```

### Setting Adjustment Values

Once you know the valid range, you can set a specific value using the `Video_CaptureDevice_VideoAdjust_SetValueAsync` method:

```
// Create an adjustment value object with your desired settings
// You can specify a custom value and whether automatic adjustment should be used
var adjustmentValue = new VideoCaptureDeviceAdjustValue(75, false); // Value: 75, Auto: false

// Apply the brightness adjustment to the camera
await VideoCapture1.Video_CaptureDevice_VideoAdjust_SetValueAsync(VideoHardwareAdjustment.Brightness, adjustmentValue);
```

### Retrieving Current Values

To read the current value of any adjustment property, use the `Video_CaptureDevice_VideoAdjust_GetValueAsync` method:

```
// Get the current brightness setting from the camera
// This returns both the current value and whether auto-adjustment is enabled
var currentBrightness = await VideoCapture1.Video_CaptureDevice_VideoAdjust_GetValueAsync(VideoHardwareAdjustment.Brightness);

// Access the current value and auto flag
int value = currentBrightness.Value;
bool isAuto = currentBrightness.Auto;
```

## Best Practices for Camera Adjustments

1. **Always check ranges first**: Different camera models have different valid ranges for each property.
2. **Handle unsupported properties**: Always implement error handling for properties that might not be supported.
3. **Consider saving user preferences**: Store adjustment values in application settings for a consistent experience.
4. **Provide UI controls**: Create sliders with proper min/max values based on the ranges returned.
5. **Consider automatic vs. manual**: Some users may prefer auto-adjustment while others need precise manual control.

## Implementation Example with C# Code

The form has a `VideoView`, combo boxes for the camera, format and frame rate, and Start, Stop and Save Frame buttons; Stop and Save Frame start disabled. The designer file is in the source code above. The project targets .NET 10 with implicit usings. On .NET Framework 4.7.2, the same code builds in an SDK-style project with `<LangVersion>10</LangVersion>` and `<ImplicitUsings>enable</ImplicitUsings>`; in `Program.cs`, replace `ApplicationConfiguration.Initialize()`, which .NET Framework does not generate, with `Application.EnableVisualStyles()` and `Application.SetCompatibleTextRenderingDefault(false)`, and set `<dpiAware>true</dpiAware>` in an `app.manifest` to keep the system DPI awareness that .NET 10 sets.

```
using System.ComponentModel;
using System.Diagnostics;
using System.Drawing.Imaging;
using VisioForge.Core.Types;
using VisioForge.Core.Types.VideoCapture;
using VisioForge.Core.UI;
using VisioForge.Core.VideoCapture;

namespace WebcamPreview;

public partial class Form1 : Form
{
    private VideoCaptureCore videoCapture1 = null!;

    public Form1()
    {
        InitializeComponent();
    }

    private void Form1_Load(object sender, EventArgs e)
    {
        videoCapture1 = new VideoCaptureCore(VideoView1 as IVideoView);

        // Show SDK errors in the title bar
        videoCapture1.OnError += (_, args) => BeginInvoke(() => Text = args.Message);

        foreach (var device in videoCapture1.Video_CaptureDevices())
            cbCamera.Items.Add(device.Name);

        if (cbCamera.Items.Count > 0) cbCamera.SelectedIndex = 0;
    }

    private void cbCamera_SelectedIndexChanged(object sender, EventArgs e)
    {
        cbFormat.Items.Clear();
        cbFrameRate.Items.Clear();
        var device = videoCapture1.Video_CaptureDevices().First(d => d.Name == cbCamera.Text);
        foreach (var format in device.VideoFormats)
            cbFormat.Items.Add(format.Name);

        var index = cbFormat.Items.IndexOf("1920x1080 MJPG, 24 bit");
        if (cbFormat.Items.Count > 0) cbFormat.SelectedIndex = index >= 0 ? index : 0;
    }

    private void cbFormat_SelectedIndexChanged(object sender, EventArgs e)
    {
        cbFrameRate.Items.Clear();
        var device = videoCapture1.Video_CaptureDevices().First(d => d.Name == cbCamera.Text);
        var format = device.VideoFormats.First(f => f.Name == cbFormat.Text);
        foreach (var frameRate in format.FrameRates)
            cbFrameRate.Items.Add(frameRate);

        var rate = cbFrameRate.Items.IndexOf(VideoFrameRate.FPS_30);
        if (cbFrameRate.Items.Count > 0) cbFrameRate.SelectedIndex = rate >= 0 ? rate : 0;
    }

    private async void btStart_Click(object sender, EventArgs e)
    {
        Text = cbFrameRate.SelectedItem is null ? "No camera, format or frame rate" : "Webcam preview";
        if (cbFrameRate.SelectedItem is null) return;

        videoCapture1.Video_CaptureDevice = new VideoCaptureSource(cbCamera.Text);
        var camera = videoCapture1.Video_CaptureDevice;
        camera.Format_UseBest = false;
        camera.Format = cbFormat.Text;
        camera.FrameRate = (VideoFrameRate)cbFrameRate.SelectedItem;

        // Video only: audio playback is on by default
        videoCapture1.Audio_PlayAudio = false;
        videoCapture1.Mode = VideoCaptureMode.VideoPreview;

        btStart.Enabled = false;
        var started = await videoCapture1.StartAsync();
        btStop.Enabled = started;
        btSaveFrame.Enabled = started;
        btStart.Enabled = !started;
    }

    private async void btSaveFrame_Click(object sender, EventArgs e)
    {
        // A new JPEG in Pictures on every click, at the camera's own resolution
        var file = Path.Combine(
            Environment.GetFolderPath(Environment.SpecialFolder.MyPictures),
            $"frame-{DateTime.Now:yyyyMMdd-HHmmss-fff}.jpg");

        if (!await videoCapture1.Frame_SaveAsync(file, ImageFormat.Jpeg, 85)) return;

        // Open it in the default viewer; with no app for .jpg, the path in the title is all there is
        Text = file;
        try { Process.Start(new ProcessStartInfo(file) { UseShellExecute = true }); }
        catch (Win32Exception) { }
    }

    private async void btStop_Click(object sender, EventArgs e)
    {
        btStop.Enabled = false;
        btSaveFrame.Enabled = false;
        await videoCapture1.StopAsync();
        btStart.Enabled = true;
    }

    private void Form1_FormClosing(object sender, FormClosingEventArgs e)
    {
        // Starting or stopping: wait for it before closing
        if (!btStart.Enabled && !btStop.Enabled)
        {
            e.Cancel = true;
            return;
        }

        // Dispose stops a running preview: there is no file to finish
        videoCapture1.Dispose();
    }
}
```

## Key Implementation Features

1. **Preview mode** - `Mode = VideoCaptureMode.VideoPreview` puts the camera on screen and writes no file, so there is no `Output_Filename` and no `Output_Format` to set. The frames still reach the app, which is what `Frame_SaveAsync` uses. Switch the mode to `VideoCapture`, add an output file and a format, and the same app records
2. **Camera format** - with `Format_UseBest` left on, the engine picks the highest resolution up to 1080p by itself; the sample turns it off and passes the format and the frame rate picked in the lists
3. **Audio** - `Audio_PlayAudio` is `true` by default and plays the audio source selected in `Audio_CaptureDevice` through the speakers, or, for a capture card whose video filter has an audio pin, the video source itself (`IsAudioSource`; a USB webcam microphone is a separate audio device). The sample shows video only, so it turns it off; left on with neither, the engine raises `OnError` ("The audio source is not configured"), sets `Audio_PlayAudio` to `false` and runs without sound
4. **Saving a frame** - `Frame_SaveAsync(filename, format, quality = 85, customWidth = 0, customHeight = 0)` writes the current frame in any `ImageFormat`, like JPEG, PNG, BMP or TIFF. The quality applies to JPEG only. Set both a width and a height to resize the frame; without them, the file has the camera's resolution (1920x1080 here), not the size of the preview on screen
5. **When saving fails** - `Frame_SaveAsync` returns `false` and raises `OnError` when the preview is not running or no frame has arrived yet. The sample enables Save Frame only after `StartAsync` returns `true`
6. **New file per click** - the file name carries the date and time down to the millisecond, so a frame never replaces the previous one
7. **Opening the file** - `Process.Start` with `UseShellExecute = true` opens the JPEG in the default image viewer. On a PC with no app for `.jpg` it throws a `Win32Exception`, and the path in the title bar is what is left
8. **Closing** - `Dispose()` stops a running preview, and a preview has no file to finish, so the close handler only waits while the preview is starting or stopping

## Frames in Memory

To work on a frame without a file:

- `Frame_GetCurrent()` returns the current frame as a `System.Drawing.Bitmap`;
- the `OnVideoFrameBitmap` event hands you every frame as it arrives.

StartAsync returns once the preview is running, and then Stop and Save Frame are enabled. VideoPreview puts the camera on screen and writes no file, so there's no encoder and no output format to set. The frames still reach the app, which is what Save Frame uses. Switch the mode to VideoCapture, add an output file and a format, and the same app records.

### Save a frame

Save Frame builds a file name in the Pictures folder, with the date and time down to the millisecond, so every click makes a new file. Frame\_SaveAsync writes the current frame there as a JPEG, at quality 85, and returns false when it can't. Then the path goes to the title bar, and Process.Start with UseShellExecute opens the file in the default image viewer. On a PC with no app for JPEG files, Process.Start throws a Win32Exception, and the path in the title is what's left. Frame\_SaveAsync takes the file name and an image format, like JPEG, PNG, BMP or TIFF. The quality applies to JPEG only, and it's 85 by default. Set both a width and a height, and the frame is resized to them. Without them, the file has the camera's resolution, not the size of the preview on screen. It returns false, and raises OnError, when the preview isn't running or no frame has arrived yet.

### Stop and close

Stop disables Stop and Save Frame, and StopAsync stops the camera. In the Properties window, on the Events tab, double-click FormClosing to add this handler. While the preview is starting or stopping, both buttons are disabled, and the handler waits by cancelling the close. Otherwise it disposes the engine. Dispose stops a running preview, and there's no file to finish.

### Run it

Run the app from Visual Studio. The camera and format lists fill in from the devices. Start begins the preview. The C920 takes a few seconds to send its first frame, and then the picture appears. Click Save Frame. The JPEG opens in Photos. Its size is 1920 by 1080, the camera's format, although the preview on the form is much smaller. Close Photos, stop the preview, and close the window.

### Common mistakes

A few common mistakes. Audio\_PlayAudio left on with no audio source selected, so OnError reports a missing audio source. Saving before Start, or before the camera sends its first frame, so Frame\_SaveAsync returns false. One file name for every click, so each frame replaces the last. And a quality value with PNG or BMP, where it's ignored.

## Implementation Example with C# Code

The form has a `VideoView` named `VideoView1`, the text boxes `edURL`, `edLogin` and `edPassword` (with `UseSystemPasswordChar`), a **Record audio** check box `cbRecordAudio`, and the buttons `btStart` and `btStop`, both disabled in the designer. The form's `Load` and `FormClosing` events are wired to the handlers below.

```
using VisioForge.Core;
using VisioForge.Core.Types.X.Output;
using VisioForge.Core.Types.X.Sources;
using VisioForge.Core.VideoCaptureX;

namespace IpCameraCaptureMp4;

public partial class Form1 : Form
{
    private VideoCaptureCoreX videoCapture1 = null!;

    private string outputFile = string.Empty;

    public Form1()
    {
        InitializeComponent();
    }

    private async void Form1_Load(object sender, EventArgs e)
    {
        await VisioForgeX.InitSDKAsync();

        videoCapture1 = new VideoCaptureCoreX(VideoView1);

        // Show SDK errors in the title bar
        videoCapture1.OnError += (_, args) => BeginInvoke(() => Text = args.Message);

        btStart.Enabled = true;
    }

    private async void btStart_Click(object sender, EventArgs e)
    {
        if (!Uri.TryCreate(edURL.Text, UriKind.Absolute, out var url))
        {
            Text = "Enter the camera URL";
            return;
        }

        Text = "Connecting...";
        btStart.Enabled = false;
        cbRecordAudio.Enabled = false;

        var started = false;
        try
        {
            // Reads the stream info first: audio is recorded only when the info shows an audio track
            videoCapture1.Video_Source = await RTSPSourceSettings.CreateAsync(url, edLogin.Text, edPassword.Text, cbRecordAudio.Checked);

            videoCapture1.Audio_Record = cbRecordAudio.Checked;
            videoCapture1.Audio_Play = false; // record the camera's sound, don't play it

            // H.264 on the GPU encoder when there is one, OpenH264 otherwise; AAC audio
            outputFile = Path.Combine(Environment.GetFolderPath(Environment.SpecialFolder.MyVideos), $"ipcam_{DateTime.Now:yyyyMMdd_HHmmss}.mp4");
            videoCapture1.Outputs_Clear();
            videoCapture1.Outputs_Add(new MP4Output(outputFile));

            started = await videoCapture1.StartAsync();
        }
        catch (Exception ex)
        {
            Text = ex.Message;
        }

        // An SDK error posted during the start stays in the title
        if (Text == "Connecting...") Text = started ? "Recording..." : "The recording did not start";
        btStop.Enabled = started;
        btStart.Enabled = !started;
        cbRecordAudio.Enabled = !started;
    }

    private async void btStop_Click(object sender, EventArgs e)
    {
        btStop.Enabled = false;
        await videoCapture1.StopAsync(); // finishes the MP4 file
        Text = "Saved: " + outputFile;
        btStart.Enabled = true;
        cbRecordAudio.Enabled = true;
    }

    private async void Form1_FormClosing(object sender, FormClosingEventArgs e)
    {
        if (!btStart.Enabled && !btStop.Enabled)
        {
            e.Cancel = true; // loading, starting or stopping: wait for it
            return;
        }

        if (btStop.Enabled)
        {
            e.Cancel = true; // recording: finish the MP4 first
            btStop.Enabled = false;
            await videoCapture1.StopAsync();
            btStart.Enabled = true;
            BeginInvoke(Close);
            return;
        }

        videoCapture1.Dispose();
        VisioForgeX.DestroySDK();
    }
}
```

## Key Implementation Features

1. **SDK initialization** - `VisioForgeX.InitSDKAsync` runs once, when the form loads. The first run on a PC takes longer, so Start is enabled only after it returns. `VisioForgeX.DestroySDK` releases it when the form closes
2. **The camera's address** - `rtsp://`, the camera's IP address and port (usually 554), then a path that differs per brand. The login and the password are separate arguments of `CreateAsync`, so the URL does not carry them. An `http://` address is taken as the camera's ONVIF service, and the RTSP URL of its best profile is read from it. The [IP camera brands directory](../../../camera-brands/) lists the paths of many cameras
3. **Audio** - with **Record audio** checked, `CreateAsync` asks for the camera's audio and `Audio_Record` puts it in the file. The audio is recorded only when the stream info shows an audio track, so a camera without a microphone gives a video-only file. `Audio_Play` is `true` by default; the app sets it to `false`, so the sound is recorded but not played
4. **MP4 output** - `MP4Output` with no encoder settings picks NVIDIA NVENC, then AMD AMF, then Intel Quick Sync, and OpenH264 on the CPU when none of them is present. Audio is AAC. An output stays in the engine after a recording, so `Outputs_Clear` runs before each new one
5. **Starting** - a camera that does not answer takes a while to fail, so the title says "Connecting..." and Start is disabled until `StartAsync` returns. An `OnError` message posted during the start stays in the title
6. **Stopping and closing** - `StopAsync` finalizes the MP4 file. Closing the form during a recording cancels the close, awaits `StopAsync`, and closes again; while the SDK is loading, or a start or a stop is under way, the close waits

## Troubleshooting

- **The camera refuses the stream** - the path does not match the camera's brand, or the login or password is wrong. The error is shown in the window title
- **The file has no sound** - the camera sends no audio track, or audio is turned off in the camera's own settings
- **Choosing the encoder** - to stay on the CPU, pass `new OpenH264EncoderSettings()` (namespace `VisioForge.Core.Types.X.VideoEncoders`) to the `MP4Output` constructor; `H264EncoderBlock.CanEncodeAsync` (namespace `VisioForge.Core.MediaBlocks.VideoEncoders`) tests whether a GPU encoder can encode right now
- **Several cameras** - use one `VideoCaptureCoreX` and one `VideoView` for each

```
        if (!Uri.TryCreate(edURL.Text, UriKind.Absolute, out var url))
        {
            Text = "Enter the camera URL";
            return;
        }

        // The URL stays free of credentials: login and password go separately
        videoCapture1.IP_Camera_Source = new IPCameraSourceSettings
        {
            URL = url,
            Login = edLogin.Text,
            Password = edPassword.Text,
            Type = IPSourceEngine.Auto_LAV
        };

        // Video only: audio playback is on by default
        videoCapture1.Audio_PlayAudio = false;

        // Effects are set before the start
        videoCapture1.Video_Effects_Clear();
        videoCapture1.Video_Effects_Enabled = cbPixelate.Checked;
        if (cbPixelate.Checked)
            videoCapture1.Video_Effects_Add(new VideoEffectMosaic(true, 40));

        videoCapture1.Mode = VideoCaptureMode.IPPreview;

        // A camera that does not answer takes up to ~20 s to fail
        Text = "Connecting...";
        btStart.Enabled = false;
        cbPixelate.Enabled = false;
        var started = await videoCapture1.StartAsync();

        // An SDK error posted during the start stays in the title
        if (Text == "Connecting...") Text = started ? "IP camera preview" : "The preview did not start";
        btStop.Enabled = started;
        btStart.Enabled = !started;
        cbPixelate.Enabled = !started;
    }

    private async void btStop_Click(object sender, EventArgs e)
    {
        btStop.Enabled = false;
        await videoCapture1.StopAsync();
        btStart.Enabled = true;
        cbPixelate.Enabled = true;
    }

    private void Form1_FormClosing(object sender, FormClosingEventArgs e)
    {
        // Starting or stopping: wait for it before closing
        if (!btStart.Enabled && !btStop.Enabled)
        {
            e.Cancel = true;
            return;
        }

        // Dispose stops a running preview: there is no file to finish
        videoCapture1.Dispose();
    }
}
```

## Key Implementation Features

1. **Credentials out of the URL** - `Login` and `Password` are properties of `IPCameraSourceSettings`, so the URL never carries them and they never show up wherever the address is shown or logged. The password text box sets `UseSystemPasswordChar`, so it shows dots
2. **The engine** - `IPSourceEngine.Auto_LAV` reads RTSP and HTTP streams with LAV Filters and can decode on the GPU. Without the LAV redist the start fails with "Unable to create LAV Splitter Source filter"
3. **The camera's address** - `rtsp://`, the camera's IP address and port (usually 554), then a path that differs per brand. Many cameras send a full-resolution main stream and a smaller sub stream; the camera's manual or web page gives the exact path, and the [IP camera brands directory](../../../camera-brands/) lists many of them
4. **Preview mode** - `Mode = VideoCaptureMode.IPPreview` shows the camera and writes no file. Add the MP4 redist ([x64](https://www.nuget.org/packages/VisioForge.DotNet.Core.Redist.MP4.x64/), [x86](https://www.nuget.org/packages/VisioForge.DotNet.Core.Redist.MP4.x86/)), switch to `IPCapture`, set an output file and a format, and the same app records; [Record RTSP stream to MP4](../ip-camera-capture-mp4/) shows the same recording on the cross-platform `VideoCaptureCoreX`
5. **Audio** - `Audio_PlayAudio` is `true` by default; the sample shows video only, so it turns it off
6. **Pixelate** - `VideoEffectMosaic(enabled, value)` takes the block size in pixels, from 1 to 255: 2 to 5 is a light effect, 16 and up leaves nothing readable. It covers the whole frame, in the preview and in a recording alike. Effects are set before `StartAsync`, so the check box is locked while the preview runs, and `Video_Effects_Clear` removes the previous run's effect
7. **Starting** - a camera that does not answer takes up to about 20 seconds to fail, so the title says "Connecting..." and Start is disabled until `StartAsync` returns. An `OnError` message posted during the start stays in the title
8. **Closing** - `Dispose()` stops a running preview, and a preview has no file to finish, so the close handler only waits while the preview is starting or stopping

## Troubleshooting

- **The camera connects but the picture stays black** - the LAV engine receives RTSP video over UDP, and a firewall, a NAT or a VPN that blocks UDP stops it; a virtual machine on NAT networking does this too. Allow UDP from the camera, or use `IPSourceEngine.RTSP_LowLatency`, which reads RTSP over TCP by default (`RTSP_LowLatency_UseUDP` is `false`)
- **The camera refuses the stream** - the path does not match the camera's brand, or the login or password is wrong
- **Several cameras** - use one `VideoCaptureCore` and one `VideoView` for each
- **Finding cameras** - `IP_Camera_ONVIF_ListSourcesAsync` discovers ONVIF cameras on the network

```
using System.ComponentModel;
using System.Windows;
using VisioForge.Core;
using VisioForge.Core.Types.X.AudioRenderers;
using VisioForge.Core.Types.X.Output;
using VisioForge.Core.Types.X.Sources;
using VisioForge.Core.VideoCaptureX;

namespace IpCameraTwoWayAudioWpf;

public partial class MainWindow : Window
{
    private VideoCaptureCoreX videoCapture1 = null!;

    private AudioCaptureDeviceInfo[] microphones = null!;

    private AudioOutputDeviceInfo[] speakers = null!;

    public MainWindow()
    {
        InitializeComponent();
    }

    private async void Window_Loaded(object sender, RoutedEventArgs e)
    {
        await VisioForgeX.InitSDKAsync();

        videoCapture1 = new VideoCaptureCoreX(VideoView1);

        // Show SDK errors in the title bar
        videoCapture1.OnError += (_, args) => Dispatcher.InvokeAsync(() => Title = args.Message);

        microphones = await DeviceEnumerator.Shared.AudioSourcesAsync();
        foreach (var device in microphones)
            cbMicrophone.Items.Add(device.DisplayName);

        if (cbMicrophone.Items.Count > 0) cbMicrophone.SelectedIndex = 0;

        speakers = await DeviceEnumerator.Shared.AudioOutputsAsync(AudioOutputDeviceAPI.WASAPI2);
        foreach (var device in speakers)
            cbSpeakers.Items.Add(device.DisplayName);

        // Preselect the system's default output
        if (cbSpeakers.Items.Count > 0) cbSpeakers.SelectedIndex = Math.Max(0, Array.FindIndex(speakers, device => device.IsDefault));

        btStart.IsEnabled = true;
    }

    private async void btStart_Click(object sender, RoutedEventArgs e)
    {
        if (!Uri.TryCreate(edURL.Text, UriKind.Absolute, out var url))
        {
            Title = "Enter the camera URL";
            return;
        }

        if (cbMicrophone.SelectedIndex < 0)
        {
            Title = "No microphone";
            return;
        }

        Title = "Connecting...";
        btStart.IsEnabled = false;

        var started = false;
        try
        {
            // The camera's video and its own microphone, played on the chosen speakers
            videoCapture1.Video_Source = await RTSPSourceSettings.CreateAsync(url, edLogin.Text, edPassword.Password, audioEnabled: true);
            videoCapture1.Audio_OutputDevice = cbSpeakers.SelectedIndex < 0 ? null : new AudioRendererSettings(speakers[cbSpeakers.SelectedIndex]);
            videoCapture1.Audio_Play = true;

            // The PC microphone, sent to the camera speaker over the ONVIF audio backchannel
            videoCapture1.Audio_BackchannelSource = microphones[cbMicrophone.SelectedIndex].CreateSourceSettingsVC();

            started = await videoCapture1.StartAsync();
        }
        catch (Exception ex)
        {
            Title = ex.Message;
        }

        // An SDK error posted during the start stays in the title
        if (Title == "Connecting...") Title = started ? "Talking to the camera" : "The camera did not start";
        btStop.IsEnabled = started;
        btStart.IsEnabled = !started;
    }

    private async void btStop_Click(object sender, RoutedEventArgs e)
    {
        btStop.IsEnabled = false;
        await videoCapture1.StopAsync();
        Title = "IP Camera Two-Way Audio";
        btStart.IsEnabled = true;
    }

    private async void Window_Closing(object sender, CancelEventArgs e)
    {
        if (btStart.IsEnabled)
        {
            videoCapture1.Dispose();
            VisioForgeX.DestroySDK();
            return;
        }

        e.Cancel = true; // still loading or talking: stop first
        if (!btStop.IsEnabled) return; // already loading, starting or stopping
        btStop.IsEnabled = false;
        await videoCapture1.StopAsync();
        btStart.IsEnabled = true;
        await Dispatcher.InvokeAsync(Close); // not Close(): WPF throws inside Closing
    }
}
```

## Key Implementation Features

1. **SDK initialization** - `VisioForgeX.InitSDKAsync` runs once, when the window loads. The first run on a PC takes longer, so Start is enabled only after it returns. `VisioForgeX.DestroySDK` releases it when the window closes
2. **The camera** - `RTSPSourceSettings.CreateAsync` takes the URL, the login and the password as separate arguments, so the URL does not carry them. With `audioEnabled: true` the camera's own sound is used when its stream has one, and `Audio_Play` plays it on the speakers set in `Audio_OutputDevice`, since `Audio_Source` is left empty. Without `Audio_OutputDevice` it plays on the system default output. The [IP camera brands directory](../../../camera-brands/) lists the RTSP paths of many cameras
3. **The backchannel** - `Audio_BackchannelSource` takes the same audio sources as `Audio_Source`; `CreateSourceSettingsVC` turns the chosen microphone into one. At the start the SDK asks the camera for its ONVIF audio backchannel and sends the microphone to it as G.711 mu-law (PCMU), 8000 Hz, the codec ONVIF requires from every camera with an audio output; a camera whose backchannel offers only G.711 A-law (PCMA) gets A-law. The sound leaves the PC as it is captured, without the RTSP receive buffer added on top
4. **Starting** - a camera that does not answer takes a while to fail, so the title says "Connecting..." and Start is disabled until `StartAsync` returns. An `OnError` message posted during the start stays in the title
5. **Stopping and closing** - `StopAsync` closes both directions. Closing the window while it runs cancels the close, awaits `StopAsync`, and closes again; while the SDK is loading, or a start or a stop is under way, the close is cancelled: close the window again once it is done

## Troubleshooting

- **The camera refuses the connection** - the path does not match the camera's brand, or the login or password is wrong. Several wrong passwords in a row make many cameras lock the account for a while
- **No picture at all, with the right URL and password** - asking for the backchannel adds the ONVIF `Require: www.onvif.org/ver20/backchannel` header to the DESCRIBE request and to the backchannel's SETUP, and a camera without a backchannel may refuse either (it answers 551 Option Not Supported): an error then replaces the title, even when the start has already reported success. Leave `Audio_BackchannelSource` empty and start again: if the picture comes, the camera has no backchannel
- **The picture comes, but the camera speaker is silent** - the camera offers no backchannel, or neither G.711 mu-law nor A-law at 8000 Hz: the SDK names the codecs the camera offers in the window title. Check that two-way audio is on in the camera's web interface, that no vendor app or NVR holds its talk channel, and raise the speaker volume (see [Speaker Volume over ONVIF](../../video-sources/ip-cameras/two-way-audio/#speaker-volume-over-onvif))
- **You do not hear yourself through the camera's microphone** - this is expected. Cameras with a speaker cancel it in their microphone, so check the speaker by ear, next to the camera
- **The person at the camera hears an echo** - the PC plays the camera's sound on its speakers while its microphone sends to the camera, so the PC microphone picks the camera's sound up again and sends it back. Use a headset on the PC, or set `Audio_Play` to `false`

## When to Use AVI for Screen Recording

- **Every frame is a whole picture** - with MJPEG, you can cut and edit on any frame, and read each frame on its own for analysis, without decoding the frames before it
- **No audio loss** - a plain `AVIOutput` writes uncompressed PCM
- **DirectShow tools** - AVI with MJPEG opens in DirectShow-based editors and players on Windows

**Trade-off:** size. In the video, a 4K screen at 10 frames per second with MJPEG takes about 30 MB a second: 679 MB for 22 seconds, about 110 GB an hour. For the web, phones and sharing, record [MP4 with H.264](../screen-capture-mp4/) instead.

```
using VisioForge.Core.Types;
using VisioForge.Core.Types.Output;
using VisioForge.Core.Types.VideoCapture;
using VisioForge.Core.UI;
using VisioForge.Core.VideoCapture;

namespace ScreenCaptureAvi;

public partial class Form1 : Form
{
    private VideoCaptureCore videoCapture1 = null!;

    public Form1()
    {
        InitializeComponent();
    }

    // The engine names a monitor by the N of its device name, \\.\DISPLAYN
    private static int MonitorNumber(Screen screen) =>
        int.Parse(screen.DeviceName.Replace(@"\\.\DISPLAY", string.Empty));

    private void Form1_Load(object sender, EventArgs e)
    {
        videoCapture1 = new VideoCaptureCore(VideoView1 as IVideoView);

        // Show SDK errors in the title bar
        videoCapture1.OnError += (_, args) => BeginInvoke(() => Text = args.Message);

        foreach (var screen in Screen.AllScreens)
            cbMonitor.Items.Add(MonitorNumber(screen));

        cbMonitor.SelectedItem = MonitorNumber(Screen.PrimaryScreen!);

        cbFrameRate.Items.AddRange(new object[] { 5, 10, 15, 25, 30 });
        cbFrameRate.SelectedItem = 10;

        // "VisioForge What You Hear Source" records what plays on the speakers
        foreach (var device in videoCapture1.Audio_CaptureDevices())
            cbSound.Items.Add(device.Name);

        cbSound.SelectedItem = "VisioForge What You Hear Source";
        if (cbSound.SelectedIndex < 0 && cbSound.Items.Count > 0) cbSound.SelectedIndex = 0;
        cbRecordSound.Enabled = cbMP3.Enabled = cbSound.Items.Count > 0;
        cbRecordSound.CheckedChanged += (_, _) => cbMP3.Enabled = cbRecordSound.Checked; // MP3 needs sound

        // The video codecs installed on this PC
        foreach (var codec in videoCapture1.Video_Codecs())
            cbVideoCodec.Items.Add(codec);

        cbVideoCodec.SelectedItem = "MJPEG Compressor";
        if (cbVideoCodec.SelectedIndex < 0 && cbVideoCodec.Items.Count > 0) cbVideoCodec.SelectedIndex = 0;
    }

    private async void btStart_Click(object sender, EventArgs e)
    {
        if (cbVideoCodec.SelectedItem is null)
        {
            Text = "No video codec selected";
            return;
        }

        Text = "Screen to AVI";

        // The whole monitor at the frame rate from the list
        videoCapture1.Screen_Capture_Source = new ScreenCaptureSourceSettings
        {
            FullScreen = true,
            AllowDesktopDuplicationEngine = true, // DXGI Desktop Duplication: faster than GDI
            DisplayIndex = (int)cbMonitor.SelectedItem!,
            GrabMouseCursor = cbCursor.Checked,
            FrameRate = new VideoFrameRate((int)cbFrameRate.SelectedItem!)
        };

        var recordSound = cbRecordSound.Checked && cbSound.SelectedItem is not null;
        videoCapture1.Audio_RecordAudio = recordSound;
        // No device when the sound is off: a What You Hear device left here still opens the speakers
        videoCapture1.Audio_CaptureDevice = recordSound ? new AudioCaptureSource(cbSound.Text) : null;
        videoCapture1.Audio_PlayAudio = false; // never play the captured sound back into the speakers

        // Audio: MP3, or uncompressed PCM
        var avi = recordSound && cbMP3.Checked ? new AVIOutput(new MP3Output()) : new AVIOutput();
        avi.Video_Codec = cbVideoCodec.Text;

        videoCapture1.Output_Filename = Path.Combine(
            Environment.GetFolderPath(Environment.SpecialFolder.MyVideos), "output.avi");
        videoCapture1.Output_Format = avi;
        videoCapture1.Mode = VideoCaptureMode.ScreenCapture;

        btStart.Enabled = false;
        var started = await videoCapture1.StartAsync();
        btStop.Enabled = started;
        btStart.Enabled = !started;
    }

    private async void btStop_Click(object sender, EventArgs e)
    {
        btStop.Enabled = false;
        await videoCapture1.StopAsync();
        btStart.Enabled = true;
    }

    private async void Form1_FormClosing(object sender, FormClosingEventArgs e)
    {
        // Finish the AVI before the window goes away
        if (!btStart.Enabled)
        {
            e.Cancel = true;
            if (!btStop.Enabled) return; // already starting or stopping

            btStop.Enabled = false;
            await videoCapture1.StopAsync();
            btStart.Enabled = true;
            BeginInvoke(Close); // close again once this handler has returned
            return;
        }

        videoCapture1.Dispose();
    }
}
```

## Key Implementation Features

1. **Monitor** - `DisplayIndex` takes the number at the end of the monitor's Windows device name, `\\.\DISPLAY1` → `1`; `MonitorNumber` reads it from `Screen.DeviceName`, and the primary monitor is selected
2. **Screen Source** - `FullScreen` records the whole monitor at its full resolution, and `AllowDesktopDuplicationEngine` captures through Windows Desktop Duplication instead of GDI. `GrabMouseCursor` is off by default and `FrameRate` is 10 by default
3. **Speaker Sound** - `VisioForge What You Hear Source`, from the video capture redist, records what plays on the speakers. With Record sound off, the app sets `Audio_RecordAudio` to `false` and clears `Audio_CaptureDevice` too, and `Audio_PlayAudio` stays `false` so the recorded sound isn't played back into the speakers
4. **Video Codec** - `Video_Codecs()` returns the DirectShow video compressors installed on the PC; `AVIOutput.Video_Codec` takes one of those names and defaults to `MJPEG Compressor`, which stores every frame as a JPEG picture
5. **Audio** - A plain `AVIOutput` writes uncompressed PCM, 16-bit stereo at 44.1 kHz, about ten megabytes a minute; `new AVIOutput(new MP3Output())` writes MP3 at 192 kbps, about one and a half megabytes a minute
6. **Asynchronous Operation** - `StartAsync` and `StopAsync` keep the UI responsive, and closing the form finishes the AVI file first

## Frequently Asked Questions

### Why is my AVI screen recording file so large?

MJPEG compresses each frame on its own, trading file size for editing convenience: a 4K screen at 10 frames per second takes about 30 MB a second. To reduce the size, lower the frame rate, capture a smaller region instead of the full screen (`FullScreen = false` with `Left`, `Top`, `Right` and `Bottom`), or switch to [MP4 output](../screen-capture-mp4/), whose H.264 compresses across frames.

### How do I record the sound of the computer, not the microphone?

Select `VisioForge What You Hear Source` as the `AudioCaptureSource`: it records what plays on the speakers, and it ships in the video capture redist. Keep `Audio_PlayAudio` at `false`, so the recorded sound isn't played back into the speakers.

### When should I use AVI instead of MP4 for screen recording?

Choose AVI when you need frame-independent access for video editing (MJPEG allows scrubbing to any frame without decoding previous frames), when you need lossless PCM audio, or when working with DirectShow-based tools. For all other cases, MP4 with H.264 offers better compression, smaller files, and broader cross-platform support.

Let's record the screen and the sound from the speakers to an AVI file in a C# WinForms app with the VisioForge Video Capture SDK. Here's what we build. ### AVI or MP4

When is AVI the right choice over MP4? With MJPEG, every frame of the recording is a whole picture, so you can cut and edit on any frame, and read each frame on its own for analysis. PCM audio has no loss. The price is size: here about twenty-eight megabytes every second, for a 4K screen at ten frames per second. For the web, phones and sharing, MP4 with H.264 is the better choice. That's the screen capture to MP4 video.

## The code behind the window

```
using System.ComponentModel;
using System.IO;
using System.Windows;
using VisioForge.Core;
using VisioForge.Core.Types;
using VisioForge.Core.Types.X.Output;
using VisioForge.Core.Types.X.Sources;
using VisioForge.Core.VideoCaptureX;

namespace ScreenCaptureMp4Wpf;

public partial class MainWindow : Window
{
    private VideoCaptureCoreX videoCapture1 = null!;

    private AudioOutputDeviceInfo[] speakers = null!;

    public MainWindow()
    {
        InitializeComponent();
    }

    private async void Window_Loaded(object sender, RoutedEventArgs e)
    {
        await VisioForgeX.InitSDKAsync();

        videoCapture1 = new VideoCaptureCoreX(VideoView1);

        // Show SDK errors in the title bar
        videoCapture1.OnError += (_, args) => Dispatcher.InvokeAsync(() => Title = args.Message);

        // The sound of these outputs is recorded through WASAPI loopback
        speakers = await DeviceEnumerator.Shared.AudioOutputsAsync(AudioOutputDeviceAPI.WASAPI2);
        foreach (var device in speakers)
            cbSpeakers.Items.Add(device.Name);

        if (cbSpeakers.Items.Count > 0) cbSpeakers.SelectedIndex = 0;

        btStart.IsEnabled = true;
    }

    private async void btStart_Click(object sender, RoutedEventArgs e)
    {
        // The whole primary monitor, with the mouse cursor
        videoCapture1.Video_Source = new ScreenCaptureD3D11SourceSettings
        {
            FrameRate = new VideoFrameRate(30)
        };

        var recordSound = cbRecordSound.IsChecked == true && cbSpeakers.SelectedIndex >= 0;
        videoCapture1.Audio_Source = recordSound
            ? new LoopbackAudioCaptureDeviceSourceSettings(speakers[cbSpeakers.SelectedIndex])
            : null;
        videoCapture1.Audio_Record = recordSound;
        videoCapture1.Audio_Play = false; // never play the captured sound back into the speakers

        // H.264 on the GPU encoder when there is one, OpenH264 otherwise; AAC audio
        videoCapture1.Outputs_Clear();
        videoCapture1.Outputs_Add(new MP4Output(Path.Combine(
            Environment.GetFolderPath(Environment.SpecialFolder.MyVideos), $"screen_{DateTime.Now:yyyyMMdd_HHmmss}.mp4")));

        btStart.IsEnabled = false;
        var started = await videoCapture1.StartAsync();
        btStop.IsEnabled = started;
        btStart.IsEnabled = !started;
    }

    private async void btStop_Click(object sender, RoutedEventArgs e)
    {
        btStop.IsEnabled = false;
        await videoCapture1.StopAsync();
        btStart.IsEnabled = true;
    }

    private async void Window_Closing(object sender, CancelEventArgs e)
    {
        if (btStart.IsEnabled)
        {
            videoCapture1.Dispose();
            VisioForgeX.DestroySDK();
            return;
        }

        e.Cancel = true; // still loading or recording: finish the MP4 first
        if (!btStop.IsEnabled) return; // already loading, starting or stopping
        btStop.IsEnabled = false;
        await videoCapture1.StopAsync();
        btStart.IsEnabled = true;
        await Dispatcher.InvokeAsync(Close); // not Close(): WPF throws inside Closing
    }
}
```

## How it works

1. **SDK initialization** — `VisioForgeX.InitSDKAsync` runs once, when the window loads. The first run on a PC takes longer, so Start is enabled only after it returns. `VisioForgeX.DestroySDK` releases it when the window closes.
2. **Screen source** — `ScreenCaptureD3D11SourceSettings` captures the whole primary monitor with the mouse cursor by default. It uses DXGI Desktop Duplication, which starts at once even on a still screen, and falls back to Windows Graphics Capture where Desktop Duplication is not supported. The default frame rate is 10 fps, so the code sets 30.
3. **System sound** — `AudioOutputsAsync(AudioOutputDeviceAPI.WASAPI2)` lists the speakers and headphones, and `LoopbackAudioCaptureDeviceSourceSettings` records what plays on the one picked. `Audio_Play` is `false`, so the recorded sound is not played back.
4. **MP4 output** — `MP4Output` with no encoder settings picks NVIDIA NVENC, then AMD AMF, then Intel Quick Sync, and OpenH264 on the CPU when none of them is present. Audio is AAC. An output stays in the engine after a recording, so `Outputs_Clear` runs before each new one.
5. **Start, stop and close** — `StartAsync` returns whether the capture started, and `StopAsync` finalizes the MP4 file. Closing the window during a recording cancels the close, awaits `StopAsync`, and closes again.

## Notes

- A WPF project leaves `System.IO` out of its implicit usings, so the file adds it for `Path`.
- The preview shows the screen it records, so the app window appears inside itself, in the preview and in the file. On a PC with two monitors, move the window to the one that is not recorded; with one monitor, minimize it after Start and restore it to stop.
- With **Record system sound** cleared, or with no speakers in the list, the MP4 holds video only.
- `MP4Output` picks a GPU encoder because its GStreamer element exists, which does not prove it can encode right now. `H264EncoderBlock.CanEncodeAsync` encodes a few test frames to find out; to stay on the CPU, pass `new OpenH264EncoderSettings()` to the `MP4Output` constructor.

### Code Example

```
using System;
using System.IO;
using System.Windows.Forms;
using VisioForge.Core.VideoCapture;
using VisioForge.Core.Types;
using VisioForge.Core.Types.Output;
using VisioForge.Core.Types.VideoCapture;

namespace screen_capture_mp4
{
    public partial class Form1 : Form
    {
        // Main VideoCapture component that handles all recording operations
        private VideoCaptureCore videoCapture1 = null!;

        public Form1()
        {
            InitializeComponent();
        }

        /// <summary>
        /// Starts screen recording with audio from the default device
        /// </summary>
        private async void btStartWithAudio_Click(object sender, EventArgs e)
        {
            // Configure screen capture to record the entire screen
            // ScreenCaptureSourceSettings allows fine control of capture region and parameters
            videoCapture1.Screen_Capture_Source = new ScreenCaptureSourceSettings() {
                FullScreen = true  // Capture the entire screen rather than a specific region
            };

            // Configure audio capture by selecting the first available audio input device
            // Audio_CaptureDevices() returns all connected microphones and audio inputs
            // We select the first device (index 0) in the collection
            videoCapture1.Audio_CaptureDevice = new AudioCaptureSource(
                videoCapture1.Audio_CaptureDevices()[0].Name);

            // Disable audio monitoring/playback during recording to prevent feedback
            // This means we won't hear the captured audio while recording
            videoCapture1.Audio_PlayAudio = false;

            // Enable audio recording to include sound in the output file
            videoCapture1.Audio_RecordAudio = true;

            // Set the output file location to the user's Videos folder
            // Environment.GetFolderPath ensures the path works across different Windows systems
            videoCapture1.Output_Filename = Path.Combine(
                Environment.GetFolderPath(Environment.SpecialFolder.MyVideos),
                "output.mp4");

            // Use MP4 container format with H.264 video and AAC audio codecs (standard format)
            // MP4Output can be further configured with custom encoding parameters if needed
            videoCapture1.Output_Format = new MP4Output();

            // Set the capture mode to screen recording
            // Other modes include camera capture, video file processing, etc.
            videoCapture1.Mode = VideoCaptureMode.ScreenCapture;

            // Begin the capture process asynchronously
            // Using async/await pattern to prevent UI freezing during operation
            await videoCapture1.StartAsync();
        }

        /// <summary>
        /// Starts screen recording without audio (video only)
        /// </summary>
        private async void btStartWithoutAudio_Click(object sender, EventArgs e)
        {
            // Configure screen capture for full screen recording
            // Same ScreenCaptureSourceSettings as in audio recording
            videoCapture1.Screen_Capture_Source = new ScreenCaptureSourceSettings() {
                FullScreen = true
            };

            // Disable both audio playback and recording in a single line
            // This creates a video-only MP4 file with no audio track
            videoCapture1.Audio_PlayAudio = videoCapture1.Audio_RecordAudio = false;

            // Set output file path to user's Videos directory with MP4 extension
            videoCapture1.Output_Filename = Path.Combine(
                Environment.GetFolderPath(Environment.SpecialFolder.MyVideos),
                "output.mp4");

            // Configure output as MP4 (H.264 video codec)
            videoCapture1.Output_Format = new MP4Output();

            // Set mode to screen capture
            videoCapture1.Mode = VideoCaptureMode.ScreenCapture;

            // Start screen recording asynchronously
            await videoCapture1.StartAsync();
        }

        /// <summary>
        /// Stops the current recording process safely
        /// </summary>
        private async void btStop_Click(object sender, EventArgs e)
        {
            // Stop the recording asynchronously
            // This properly finalizes the MP4 file and releases resources
            // Using async ensures UI remains responsive during file finalization
            await videoCapture1.StopAsync();
        }

        /// <summary>
        /// Initializes the VideoCapture component when the form loads
        /// </summary>
        private void Form1_Load(object sender, EventArgs e)
        {
            // Initialize the video capture component and connect it to a video preview control
            // VideoView1 should be a control on your form that implements IVideoView interface
            // This allows for live preview of the capture when desired
            videoCapture1 = new VideoCaptureCore(VideoView1 as IVideoView);
        }
    }
}
```

### How it works — VideoCaptureCore

This Windows Forms application demonstrates screen capture functionality with and without audio using VisioForge Video Capture SDK:

1. **Setup**: The `VideoCaptureCore` object is initialized in the form load event, connecting it to a video view component.
2. **Capturing with Audio**:
3. Sets screen capture to full screen mode
4. Selects the first available audio device for recording
5. Disables audio playback but enables audio recording
6. Sets the output file to MP4 format in the user's Videos folder
7. Uses asynchronous method to start capture
8. **Capturing without Audio**:
9. Similar to above but disables both audio playback and recording
10. Uses the same MP4 output format and capture mode
11. **Stopping Capture**:
12. Provides a simple stop method that asynchronously stops the recording

The application demonstrates how to configure different capture scenarios with minimal code using the SDK's fluent interface and async patterns.

#### Audio Configuration

The code example above captures microphone audio by selecting the first available device. You can select a specific audio device by name, including system audio (loopback) devices for capturing desktop sound:

```
// Select a loopback device (e.g., "Stereo Mix") for system audio capture
var devices = videoCapture1.Audio_CaptureDevices();
var loopbackDevice = devices.FirstOrDefault(d => d.Name.Contains("Stereo Mix"));

if (loopbackDevice != null)
{
    videoCapture1.Audio_CaptureDevice = new AudioCaptureSource(loopbackDevice.Name);
}
else
{
    // Fallback: use the first available audio device
    videoCapture1.Audio_CaptureDevice = new AudioCaptureSource(devices[0].Name);
}

// Enable recording, disable playback to prevent feedback
videoCapture1.Audio_RecordAudio = true;
videoCapture1.Audio_PlayAudio = false;
```

To create a silent recording with no audio track, disable both audio properties:

```
videoCapture1.Audio_PlayAudio = false;
videoCapture1.Audio_RecordAudio = false;
```

#### Region Capture

Instead of recording the full screen, capture a specific rectangular area by setting `FullScreen = false` and providing pixel coordinates:

```
videoCapture1.Screen_Capture_Source = new ScreenCaptureSourceSettings()
{
    FullScreen = false,
    Left = 100,
    Top = 100,
    Right = 1380,
    Bottom = 820
};
```

The coordinates define the capture rectangle in screen pixels. This is useful for recording a specific application window or a portion of the desktop.

#### Multi-Monitor Recording

Select which display to record using the `DisplayIndex` property. `0` is the primary monitor. A positive value is that monitor's Windows number, the digits in its device name: `\\.\DISPLAY2` is `2`. It is the same number the screen-capture samples show in the monitor list, not the monitor's position in that list, so `1` is not "the secondary monitor" (on most PCs the primary monitor is `\\.\DISPLAY1`).

```
videoCapture1.Screen_Capture_Source = new ScreenCaptureSourceSettings()
{
    FullScreen = true,
    DisplayIndex = 0  // The primary monitor
};
```

#### Recording Quality Settings

Customize the MP4 output by configuring the H.264 encoder. The default bitrate is 3500 kbps, which produces approximately 25 MB per minute at 1080p:

```
var mp4Output = new MP4Output();
mp4Output.Video.Bitrate = 5000;                          // Higher quality (kbps)
mp4Output.Video.Profile = H264Profile.ProfileMain;       // Better compression than Baseline
mp4Output.Video.RateControl = H264RateControl.VBR;       // Variable bitrate
videoCapture1.Output_Format = mp4Output;
```

#### Mouse Cursor Options

Include the mouse cursor in the recording and optionally add a highlight effect for tutorial-style screencasts:

```
videoCapture1.Screen_Capture_Source = new ScreenCaptureSourceSettings()
{
    FullScreen = true,
    GrabMouseCursor = true,
    MouseHighlight = true,
    MouseHighlightColor = System.Drawing.Color.Yellow,
    MouseHighlightRadius = 40,
    MouseHighlightOpacity = 0.4
};
```

The highlight draws a translucent circle around the cursor, making it easier for viewers to follow mouse movements.

## Console app — VideoCaptureCoreX

The cross-platform `VideoCaptureCoreX` engine also runs without a window, with Direct3D 11 screen capture (Desktop Duplication). This console application records the full screen to MP4 with optional system audio.

It takes the same packages as the WPF app: see [Required NuGet packages](#required-nuget-packages).

### Complete Example

```
using System;
using System.IO;
using System.Threading.Tasks;
using VisioForge.Core;
using VisioForge.Core.Types;
using VisioForge.Core.Types.X.Output;
using VisioForge.Core.Types.X.Sources;
using VisioForge.Core.VideoCaptureX;

class Program
{
    static async Task Main(string[] args)
    {
        // Initialize SDK
        await VisioForgeX.InitSDKAsync();

        var videoCapture = new VideoCaptureCoreX();

        try
        {
            // Configure Direct3D 11 screen capture (Desktop Duplication by default)
            var screenSource = new ScreenCaptureD3D11SourceSettings
            {
                FrameRate = new VideoFrameRate(25, 1),
                CaptureCursor = true,
                MonitorIndex = -1  // Primary monitor (0 is the first monitor)
            };

            videoCapture.Video_Source = screenSource;
            videoCapture.Video_Play = false;
            videoCapture.Audio_Play = false;
            videoCapture.Audio_Record = false;

            // Configure MP4 output (H.264 + AAC, auto-selected encoders)
            string outputPath = Path.Combine(
                Environment.GetFolderPath(Environment.SpecialFolder.MyVideos),
                $"screen_{DateTime.Now:yyyyMMdd_HHmmss}.mp4");

            var mp4Output = new MP4Output(outputPath);
            videoCapture.Outputs_Add(mp4Output, autostart: true);

            // Start recording
            await videoCapture.StartAsync();
            Console.WriteLine($"Recording to: {outputPath}");
            Console.WriteLine("Press ENTER to stop...");
            Console.ReadLine();

            // Stop and save
            await videoCapture.StopAsync();
            Console.WriteLine("Recording saved.");
        }
        finally
        {
            await videoCapture.DisposeAsync();
            VisioForgeX.DestroySDK();
        }
    }
}
```

## GPU-Accelerated Encoding

Hardware-accelerated encoding offloads H.264/HEVC compression to your GPU, significantly reducing CPU usage during high-resolution or high-FPS recording.

```
// NVIDIA NVENC H.264
var mp4Output = new MP4Output(
    outputPath,
    new NVENCH264EncoderSettings());

// Intel Quick Sync Video H.264
var mp4Output = new MP4Output(
    outputPath,
    new QSVH264EncoderSettings());

// AMD AMF H.264
var mp4Output = new MP4Output(
    outputPath,
    new AMFH264EncoderSettings());
```

HEVC (H.265) encoders are also available for better compression at the same quality: `NVENCHEVCEncoderSettings`, `QSVHEVCEncoderSettings`, `AMFHEVCEncoderSettings`.

Engine note: `MP4Output` and the X-engine

The `MP4Output` class shown in this section refers to the **X-engine** `VisioForge.Core.Types.X.Output.MP4Output`, which accepts cross-platform `*EncoderSettings` types (`NVENCH264EncoderSettings`, `OpenH264EncoderSettings`, etc.). When hardware encoding is unavailable on the X engine and you use the parameterless ctor `new MP4Output(filename)`, the SDK selects an available software encoder automatically. The classic Windows-only DirectShow engine has its own `VisioForge.Core.Types.Output.MP4Output` with a different settings shape — don't mix them.

## Screen Capture with Media Blocks SDK

The Media Blocks SDK uses a pipeline approach where you connect source, processing, and output blocks. This gives full control over the data flow and allows splitting the video stream to multiple outputs simultaneously.

```
using System;
using System.IO;
using System.Threading.Tasks;
using VisioForge.Core;
using VisioForge.Core.MediaBlocks;
using VisioForge.Core.MediaBlocks.Sources;
using VisioForge.Core.MediaBlocks.Sinks;
using VisioForge.Core.MediaBlocks.Special;
using VisioForge.Core.Types;
using VisioForge.Core.Types.X.Sources;

class Program
{
    static async Task Main(string[] args)
    {
        await VisioForgeX.InitSDKAsync();

        var pipeline = new MediaBlocksPipeline();

        try
        {
            // Screen capture source
            var screenSettings = new ScreenCaptureD3D11SourceSettings
            {
                FrameRate = new VideoFrameRate(25, 1),
                CaptureCursor = true
            };
            var screenSource = new ScreenSourceBlock(screenSettings);

            // MP4 output
            string outputPath = Path.Combine(
                Environment.GetFolderPath(Environment.SpecialFolder.MyVideos),
                $"screen_mb_{DateTime.Now:yyyyMMdd_HHmmss}.mp4");
            var mp4Sink = new MP4OutputBlock(outputPath);

            // Connect source to output
            pipeline.Connect(screenSource.Output, mp4Sink.CreateNewInput(MediaBlockPadMediaType.Video));

            // Start pipeline
            await pipeline.StartAsync();
            Console.WriteLine($"Recording to: {outputPath}");
            Console.WriteLine("Press ENTER to stop...");
            Console.ReadLine();

            await pipeline.StopAsync();
            Console.WriteLine("Recording saved.");
        }
        finally
        {
            await pipeline.DisposeAsync();
            VisioForgeX.DestroySDK();
        }
    }
}
```

## Cross-Platform Screen Capture

The SDK supports screen capture on Windows, macOS, and Linux with platform-specific source settings:

| Platform | Capture Method | Settings Class | Requirements |
| --- | --- | --- | --- |
| Windows | Direct3D 11 / WGC | `ScreenCaptureD3D11SourceSettings` | Windows 8+ (WGC: Windows 10 v1803+) |
| macOS | AVFoundation | `ScreenCaptureMacOSSourceSettings` | macOS 10.15+ (screen recording permission) |
| Linux | X11 / XDisplay | `ScreenCaptureXDisplaySourceSettings` | X11 server |

On Windows, the SDK uses DXGI Desktop Duplication by default: it starts at once, even on a still screen, and falls back to WGC where Desktop Duplication is not supported. Window capture always uses WGC. You can select WGC for a screen too; it also starts at once on a still screen:

```
var screenSource = new ScreenCaptureD3D11SourceSettings
{
    API = D3D11ScreenCaptureAPI.WGC  // Windows Graphics Capture instead of Desktop Duplication
};
```

## Frequently Asked Questions

### What license do I need for a C# screen capture application?

Video Capture SDK .NET requires a license for development and distribution. A Developer license removes the evaluation watermark and unlocks all features during development. A Release license is required when distributing your application to end users. The SDK is available in Premium edition which includes all capture modes, MP4/AVI/WMV output, and both DirectShow and GStreamer engines. You can evaluate the SDK without a license — screen capture works fully but includes a watermark overlay. Visit the [product page](https://www.visioforge.com/video-capture-sdk-net) for pricing and license options.

### How do I control recording quality and file size for MP4 screen capture?

Configure the `MP4Output` video bitrate to balance quality and file size. The default is 3500 kbps, which works well for most screen recordings. Lower the bitrate to 1500–2000 kbps for smaller files, or increase to 5000–8000 kbps for high-quality captures. Use `H264Profile.ProfileMain` or `ProfileHigh` instead of `ProfileBaseline` for better compression at the same quality. Frame rate also affects file size — 15 FPS is sufficient for presentations, while 30 FPS is better for software demos. A 1080p recording at 3500 kbps produces roughly 25 MB per minute.

### Can I capture system audio (desktop sound) instead of microphone input?

Yes. With `VideoCaptureCoreX`, pass a speaker from `DeviceEnumerator.Shared.AudioOutputsAsync(AudioOutputDeviceAPI.WASAPI2)` to `LoopbackAudioCaptureDeviceSourceSettings`, as the WPF app above does: it records whatever plays on that device, with no special driver. With `VideoCaptureCore`, call `Audio_CaptureDevices()` to enumerate all available audio devices, then select a loopback or system audio device (such as "Stereo Mix" or "What U Hear") by name. Set `Audio_RecordAudio = true` and `Audio_PlayAudio = false`. The available loopback device names depend on your audio hardware and drivers. You can record both microphone and system audio simultaneously by configuring additional audio sources.

### How do I record a specific monitor in a multi-monitor setup?

With `VideoCaptureCoreX`, set `MonitorIndex` on `ScreenCaptureD3D11SourceSettings` (`0` is the first monitor, `-1` the primary) and leave `Rectangle` empty, as it is by default, to capture that monitor whole at its native resolution. With `VideoCaptureCore`, set `DisplayIndex` on `ScreenCaptureSourceSettings`. `0` is the primary monitor. A positive value is the number in that monitor's device name (`\\.\DISPLAY2` is `2`), which `Screen.AllScreens[i].DeviceName` gives; it is not `i`. Combine with `FullScreen = true` to capture the entire selected display. You can also set `FullScreen = false` with `Left/Top/Right/Bottom` coordinates to capture a specific region on the chosen monitor.

### What frame rate should I use for screen recording?

The default frame rate is 10 FPS. Use 15 FPS for presentations, slides, and mostly static content. Use 25–30 FPS for software tutorials and UI demonstrations where smooth mouse movement matters. Use 60 FPS for game recording or high-motion content. Higher frame rates increase file size and CPU usage proportionally. Set the frame rate via `ScreenCaptureD3D11SourceSettings.FrameRate` with `VideoCaptureCoreX`, or `ScreenCaptureSourceSettings.FrameRate` with `VideoCaptureCore`.

AudioOutputsAsync with WASAPI2 lists the speakers and headphones. Their names fill the list, and the first one is selected. Start is enabled only now, once the SDK has loaded. In the Start handler, set the video source to ScreenCaptureD3D11SourceSettings. Out of the box it captures the whole primary monitor with the mouse cursor. When the checkbox is checked and a device is selected, the audio source is LoopbackAudioCaptureDeviceSourceSettings for that device, and Audio\_Record is on. Add an MP4Output that writes to the Videos folder, with the date and time in the file name, so a second recording never overwrites the first. An output stays in the engine after a recording, so Outputs\_Clear runs before each new one. With no encoder settings, MP4Output picks NVIDIA NVENC, then AMD AMF, then Intel Quick Sync, and OpenH264 on the CPU when the PC has none of them. The audio is AAC. StartAsync returns whether the capture started, and the buttons follow it. StopAsync finalizes the MP4 file. If the window closes during a recording, cancel the close, await StopAsync, and close again. On that second pass the engine is disposed and the SDK released, so the file is always complete.

## When to Use WMV for Screen Recording

WMV (Windows Media Video) uses Microsoft's Windows Media codecs and the ASF container. It remains useful in specific Windows-centric scenarios:

- **Native Windows playback** - WMV files play on Windows out of the box, and the Windows Media encoders come with Windows: no GPU and no codec pack
- **A known file size** - at a constant bitrate, the size of the file has a ceiling you know before you record
- **Smaller files than AVI** - in the video, a 4K screen at 15 frames per second takes about 33 MB a minute; in the [AVI tutorial](../screen-capture-avi/), a 4K screen at only 10 frames per second with MJPEG takes about 30 MB a second
- **Legacy enterprise environments** - many corporate environments standardize on Windows Media formats for internal video distribution

**Trade-off:** WMV is a Windows-centric format with limited support on macOS, Linux and phones. For cross-platform compatibility, [MP4 is the recommended format](../screen-capture-mp4/).

## Implementation Example with C# Code

The form has a `VideoView`, combo boxes for the monitor, frame rate, sound device, video codec, audio codec and audio format, "Mouse cursor" and "Record sound" check boxes (both checked), and Start and Stop buttons; the designer file is in the source code above. The project targets .NET 10 with implicit usings. On .NET Framework 4.7.2, `Form1.cs` builds unchanged in an SDK-style project with `<LangVersion>10</LangVersion>` and `<ImplicitUsings>enable</ImplicitUsings>`; in `Program.cs`, replace `ApplicationConfiguration.Initialize()` with `Application.EnableVisualStyles()` and `Application.SetCompatibleTextRenderingDefault(false)`.

```
using VisioForge.Core.Types;
using VisioForge.Core.Types.Output;
using VisioForge.Core.Types.VideoCapture;
using VisioForge.Core.UI;
using VisioForge.Core.VideoCapture;

namespace ScreenCaptureWmv;

public partial class Form1 : Form
{
    private VideoCaptureCore videoCapture1 = null!;

    public Form1()
    {
        InitializeComponent();
    }

    // The engine names a monitor by the N of its device name, \\.\DISPLAYN
    private static int MonitorNumber(Screen screen) =>
        int.Parse(screen.DeviceName.Replace(@"\\.\DISPLAY", string.Empty));

    private void Form1_Load(object sender, EventArgs e)
    {
        videoCapture1 = new VideoCaptureCore(VideoView1 as IVideoView);

        // Show SDK errors in the title bar
        videoCapture1.OnError += (_, args) => BeginInvoke(() => Text = args.Message);

        foreach (var screen in Screen.AllScreens)
            cbMonitor.Items.Add(MonitorNumber(screen));

        cbMonitor.SelectedItem = MonitorNumber(Screen.PrimaryScreen!);

        cbFrameRate.Items.AddRange(new object[] { 5, 10, 15, 25, 30 });
        cbFrameRate.SelectedItem = 15;

        // "VisioForge What You Hear Source" records what plays on the speakers
        foreach (var device in videoCapture1.Audio_CaptureDevices())
            cbSound.Items.Add(device.Name);

        cbSound.SelectedItem = "VisioForge What You Hear Source";
        if (cbSound.SelectedIndex < 0 && cbSound.Items.Count > 0) cbSound.SelectedIndex = 0;
        cbRecordSound.Enabled = cbAudioCodec.Enabled = cbAudioFormat.Enabled = cbSound.Items.Count > 0;
        cbRecordSound.CheckedChanged += (_, _) => cbAudioCodec.Enabled = cbAudioFormat.Enabled = cbRecordSound.Checked; // audio settings need sound

        // The Windows Media codecs that can encode at a constant bitrate
        foreach (var codec in videoCapture1.WMV_CustomProfile_VideoCodecs(WMVStreamMode.CBR))
            cbVideoCodec.Items.Add(codec);

        foreach (var codec in videoCapture1.WMV_CustomProfile_AudioCodecs(WMVStreamMode.CBR))
            cbAudioCodec.Items.Add(codec);

        cbVideoCodec.SelectedItem = "Windows Media Video 9";
        if (cbVideoCodec.SelectedIndex < 0 && cbVideoCodec.Items.Count > 0) cbVideoCodec.SelectedIndex = 0;
```

## Key Implementation Features

1. **Monitor** - `DisplayIndex` takes the number at the end of the monitor's Windows device name, `\\.\DISPLAY1` → `1`; `MonitorNumber` reads it from `Screen.DeviceName`, and the primary monitor is selected
2. **Screen Source** - `FullScreen` records the whole monitor at its full resolution, and `AllowDesktopDuplicationEngine` captures through Windows Desktop Duplication instead of GDI. `GrabMouseCursor` is off by default and `FrameRate` is 10 by default; the app records at 15
3. **Speaker Sound** - `VisioForge What You Hear Source`, from the video capture redist, records what plays on the speakers. With Record sound off, the app sets `Audio_RecordAudio` to `false` and clears `Audio_CaptureDevice` too, and `Audio_PlayAudio` stays `false` so the recorded sound isn't played back into the speakers
4. **Windows Media Codecs** - `WMV_CustomProfile_VideoCodecs(WMVStreamMode.CBR)` and `WMV_CustomProfile_AudioCodecs(WMVStreamMode.CBR)` list the Windows Media encoders that work at a constant bitrate, and `WMV_CustomProfile_AudioFormats(codec, WMVStreamMode.CBR)` lists the formats of one audio codec. Pick the names from these lists rather than typing them. Windows Media Video 9 records a 4K screen
5. **Custom Settings** - `new WMVOutput()` alone uses a built-in profile; `Mode = WMVMode.CustomSettings` takes the `Custom_Video_*` and `Custom_Audio_*` values instead. `Custom_Video_Bitrate` is in kbps, so `10000` is 10 Mbps; `Custom_Video_SizeSameAsInput` keeps the monitor's resolution, and `Custom_Video_KeyFrameInterval` is in seconds. The audio stream is written only when `Custom_Audio_StreamPresent` is `true`
6. **Asynchronous Operation** - `StartAsync` and `StopAsync` keep the UI responsive, and closing the form finishes the WMV file first

The container is ASF, the format behind WMV. `wmv3` is ffprobe's name for Windows Media Video 9, and `wmav2` is the WMA stream. ## Frequently Asked Questions

### When should I use WMV instead of MP4 for screen recording?

Choose WMV when your target audience uses Windows and you need native playback without additional codec installation, when the file size has to stay under a known ceiling, or when working within enterprise environments that standardize on Windows Media formats. For cross-platform distribution or web publishing, MP4 with H.264 is the better choice: broader device support and better compression.

### Why does my WMV file have no sound?

Check that "Record sound" is on and that `VisioForge What You Hear Source` is selected, not a microphone: it records what plays on the speakers, and it ships in the video capture redist. With sound on, `Custom_Audio_StreamPresent` must be `true` and `Custom_Audio_Format` must be a name from `WMV_CustomProfile_AudioFormats` for the selected audio codec.

### How do I set the WMV bitrate?

Set `Mode = WMVMode.CustomSettings`, `Custom_Video_Mode = WMVStreamMode.CBR` and `Custom_Video_Bitrate` in kilobits per second: `10000` is 10 Mbps. The audio bitrate is part of the audio format name, such as `CBR 128 kbps, 44100 Hz, Stereo, 16 bit`.

## Implementation Example with C# Code

The following C# implementation demonstrates how to create a Windows Forms application that captures video from a webcam and saves it to an MP4 file. The form has a `VideoView`, combo boxes for the camera, format, frame rate and microphone, and Start and Stop buttons; the designer file is in the source code above. The project targets .NET 10 with implicit usings.

```
using VisioForge.Core.Types;
using VisioForge.Core.Types.Output;
using VisioForge.Core.Types.VideoCapture;
using VisioForge.Core.Types.VideoEffects;
using VisioForge.Core.UI;
using VisioForge.Core.VideoCapture;

namespace WebcamMp4;

public partial class Form1 : Form
{
    private VideoCaptureCore videoCapture1 = null!;

    public Form1()
    {
        InitializeComponent();
    }

    private void Form1_Load(object sender, EventArgs e)
    {
        videoCapture1 = new VideoCaptureCore(VideoView1 as IVideoView);

        // Show SDK errors in the title bar
        videoCapture1.OnError += (_, args) => BeginInvoke(() => Text = args.Message);

        foreach (var device in videoCapture1.Video_CaptureDevices())
            cbCamera.Items.Add(device.Name);

        foreach (var device in videoCapture1.Audio_CaptureDevices())
            cbMicrophone.Items.Add(device.Name);

        if (cbCamera.Items.Count > 0) cbCamera.SelectedIndex = 0;
        if (cbMicrophone.Items.Count > 0) cbMicrophone.SelectedIndex = 0;
    }

    private void cbCamera_SelectedIndexChanged(object sender, EventArgs e)
    {
        cbFormat.Items.Clear();
        cbFrameRate.Items.Clear();
        var device = videoCapture1.Video_CaptureDevices().First(d => d.Name == cbCamera.Text);
        foreach (var format in device.VideoFormats)
            cbFormat.Items.Add(format.Name);

        var index = cbFormat.Items.IndexOf("1920x1080 MJPG, 24 bit");
        if (cbFormat.Items.Count > 0) cbFormat.SelectedIndex = index >= 0 ? index : 0;
    }

    private void cbFormat_SelectedIndexChanged(object sender, EventArgs e)
    {
        cbFrameRate.Items.Clear();
        var device = videoCapture1.Video_CaptureDevices().First(d => d.Name == cbCamera.Text);
        var format = device.VideoFormats.First(f => f.Name == cbFormat.Text);
        foreach (var frameRate in format.FrameRates)
            cbFrameRate.Items.Add(frameRate);

        var rate = cbFrameRate.Items.IndexOf(VideoFrameRate.FPS_30);
        if (cbFrameRate.Items.Count > 0) cbFrameRate.SelectedIndex = rate >= 0 ? rate : 0;
    }

    private async void btStart_Click(object sender, EventArgs e)
    {
        Text = cbFrameRate.SelectedItem is null ? "No camera, format or frame rate" : "Webcam to MP4";
        if (cbFrameRate.SelectedItem is null) return;

        videoCapture1.Video_CaptureDevice = new VideoCaptureSource(cbCamera.Text);
        var camera = videoCapture1.Video_CaptureDevice;
        camera.Format_UseBest = false;
        camera.Format = cbFormat.Text;
        camera.FrameRate = (VideoFrameRate)cbFrameRate.SelectedItem;

        var mic = cbMicrophone.SelectedItem as string;
        videoCapture1.Audio_RecordAudio = mic is not null; // no microphone: record video only
        if (mic is not null) videoCapture1.Audio_CaptureDevice = new AudioCaptureSource(mic);
        videoCapture1.Audio_PlayAudio = false; // record the microphone without playing it back

        var mp4 = new MP4HWOutput();

        // NVIDIA, then Intel, then AMD, then the CPU encoder
        var gpu = VideoCaptureCore.HWEncodersAvailable();
        mp4.Video.Codec =
            gpu.NVENC_H264 ? MFVideoEncoder.NVENC_H264 :
            gpu.QSV_H264 ? MFVideoEncoder.QSV_H264 :
            gpu.AMD_H264 ? MFVideoEncoder.AMD_H264 :
            MFVideoEncoder.MS_H264;

        mp4.Video.AvgBitrate = 6000; // kbps
        mp4.Video.MaxBitrate = 9000;
        mp4.Video.RateControl = MFCommonRateControlMode.PeakConstrainedVBR;
        mp4.Video.Profile = MFH264Profile.Main;
        mp4.Audio.Bitrate = 192; // AAC, kbps

        videoCapture1.Output_Filename = Path.Combine(
            Environment.GetFolderPath(Environment.SpecialFolder.MyVideos), "output.mp4");
        videoCapture1.Output_Format = mp4;
        videoCapture1.Mode = VideoCaptureMode.VideoCapture;

        videoCapture1.Video_Effects_Enabled = true;
        videoCapture1.Video_Effects_Clear();
        videoCapture1.Video_Effects_Add(new VideoEffectTextLogo(true, "text")
        {
            Text = "Hello World!", Left = 50, Top = 50, FontColor = Color.Red
        });
        videoCapture1.Video_Effects_Add(new VideoEffectTextLogo(true, "clock")
        {
            Mode = TextLogoMode.DateTime, DateTimeMask = "HH:mm:ss", Text = "",
            Left = 50, Top = 110
        });

        btStart.Enabled = false;
        var started = await videoCapture1.StartAsync();
        btStop.Enabled = started;
        btStart.Enabled = !started;
    }

    private async void btStop_Click(object sender, EventArgs e)
    {
        btStop.Enabled = false;
        await videoCapture1.StopAsync();
        btStart.Enabled = true;
    }

    private async void Form1_FormClosing(object sender, FormClosingEventArgs e)
    {
        // Finish the MP4 before the window goes away
        if (!btStart.Enabled)
        {
            e.Cancel = true;
            if (!btStop.Enabled) return; // already starting or stopping

            btStop.Enabled = false;
            await videoCapture1.StopAsync();
            btStart.Enabled = true;
            BeginInvoke(Close); // close again once this handler has returned
            return;
        }

        videoCapture1.Dispose();
    }
}
```

## Key Implementation Features

This implementation provides several important capabilities for developers:

1. **Device and Format Selection** - The camera, its format, its frame rate and the microphone are picked from lists filled from the devices themselves; with no microphone, `Audio_RecordAudio` is set to `false` and the MP4 holds video only
2. **Hardware Encoding with a CPU Fallback** - `MP4HWOutput` encodes H.264 on an NVIDIA, Intel or AMD GPU; `HWEncodersAvailable` tells which encoders the PC has, and `MS_H264` runs on the CPU when none is present
3. **Encoder Settings** - An average of 6000 kbps, peaks up to 9000 kbps, the Main profile and AAC audio at 192 kbps
4. **Text Overlay** - A fixed text and a clock that shows the current time, added as video effects
5. **Asynchronous Operation** - `StartAsync` and `StopAsync` keep the UI responsive, and closing the form finishes the MP4 file first

- `FontColor` of `VideoEffectTextLogo` is a `System.Drawing.Color`, not a WPF `Color`, so it is written in full

## Key Implementation Features

1. **Device and Format Selection** - The camera, its format, its frame rate and the microphone are picked from lists filled from the devices themselves; with no microphone, `Audio_RecordAudio` and `Custom_Audio_StreamPresent` are `false` and the WMV holds video only
2. **Camera Format** - `Format_UseBest` is on by default: it picks the highest resolution up to 1080p, then prefers MJPG and the fastest frame rate. To record 4K, or any format you choose, turn it off and set `Format` and `FrameRate`
3. **Windows Media Codecs** - `WMV_CustomProfile_VideoCodecs(WMVStreamMode.CBR)` and `WMV_CustomProfile_AudioCodecs(WMVStreamMode.CBR)` return the Windows Media encoders that can work at a constant bitrate, and `WMV_CustomProfile_AudioFormats(codec, WMVStreamMode.CBR)` the formats of one audio codec, each named by its bitrate, sample rate, channels and bits. Windows Media Video 9 is the codec for camera video; the Screen and Image codecs are made for screen recordings and still pictures, Advanced Profile is the VC-1 profile made for interlaced and broadcast video, and V7 and V8 are older versions for old players. Take every codec and format name from these lists, never type it by hand
4. **Custom Settings** - A plain `new WMVOutput()` uses the built-in "Windows Media Video 9 High (2.5 Mbps)" profile from SDK 2026.11.16 on; up to 2026.11.13 it was "Windows Media Video 9 for Local Network (768 kbps)", the profile the video names. `WMVMode.CustomSettings` takes your own codec, bitrate and size: `Custom_Video_Bitrate` is in kilobits per second, so `8000` is 8 Mbps, `Custom_Video_SizeSameAsInput` keeps the camera's resolution, and `Custom_Video_KeyFrameInterval` is in seconds. With 128 kbps audio, that is about sixty megabytes a minute
5. **Asynchronous Operation** - `StartAsync` and `StopAsync` keep the UI responsive, and closing the form finishes the WMV file first

SizeSameAsInput keeps the camera's resolution, the frame rate is the one we picked, and there's a keyframe every two seconds. The audio stream takes the codec and the format from the lists, and it's there only when we have a microphone. Then write output.wmv into the Videos folder, and switch the engine to video capture mode, so it records and not just previews. A plain WMVOutput uses a built-in profile at 768 kilobits per second, made for a local network. (From SDK 2026.11.16 on, the default is "Windows Media Video 9 High (2.5 Mbps)".) CustomSettings gives us our own codec, bitrate and size. Custom\_Video\_Bitrate is in kilobits per second, so 8000 means eight megabits. With 128 kilobits of audio, that's about sixty megabytes a minute. And a keyframe every two seconds gives the player a seek point every two seconds.

### Start and stop

Start and Stop are async. StartAsync returns once the capture is running, and StopAsync finishes writing the WMV file.

### Close the window

Closing the window while it records would leave the WMV unfinished. In the Properties window, on the Events tab, double-click FormClosing to add this handler. While recording, it cancels the close. Then it stops the recording, and closes the window again once the handler has returned. With nothing recording, the handler disposes the engine.

### Run it

Run the app from Visual Studio. The camera, format and microphone lists fill in from the devices. The video codec list shows the Windows Media encoders. Windows Media Video 9 stays selected. Start begins the recording. The C920 takes a few seconds to send its first frame. Stop finishes output.wmv, and then we close the window.

### Check the file with ffprobe

The file lands in Videos: about sixteen megabytes for sixteen seconds. ffprobe shows what's inside. The container is ASF, the format behind WMV. The video is WMV 9, which ffprobe calls wmv3, at 1920x1080. The audio is WMA, 48 kilohertz stereo.

### Common mistakes

A few common mistakes. A missing redist package, so the engine won't start. Codec and format names typed by hand: take them from the lists. Custom\_Video\_Bitrate written in bits per second: it's in kilobits. On the N editions of Windows, the Windows Media components come with the Media Feature Pack, so install it first. And closing the window mid-recording: await StopAsync first.
